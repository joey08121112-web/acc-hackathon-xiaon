本文件面向产品、设计、开发与验收成员。v1.1整合用户提供的对话式学习理念文档，把“先聊聊、继续追问、一起思考、看见进步”落实为可验证的教学交互要求，并更新A至D交付现状。两份文档定位一致：帮助学生把笼统的“我不会”变成自己能够解释和尝试的下一步。首版仍聚焦七年级数学，保留学生自主选择、五维有限观察、作答证据、计划与延迟复习。

## 1 产品定位与关键决策

### 1.1 产品要解决的问题

考试失利后的学生可能既需要被倾听，也需要找到可以处理的具体学习困难。直接要求刷题容易跳过其意愿；只提供安慰又难以连接学习行动。小N以温和对话为入口，把“我数学不行”拆成可核对的任务表现，例如一次去括号时漏改符号，而非给学生贴整体能力标签。

产品定位为对话式AI数学学习支持工具，目标是用交互带动学生主动思考。综合对话了解意愿与具体卡点；五维探索观察有限任务表现；计划与回顾把观察转成小行动。四步引导是教学过程，五维是观察内容，理解清晰度、思路完整度与学生自述信心是反馈角度，三者不能混成同一套能力评分。

### 1.2 本版已经确认的方向

- 平台先采用手机竖屏网页，兼容桌面浏览；不在本轮拆成两款产品或原生 App。
- 首期服务七年级数学，五维为理解、逻辑、计算、建模、空间想象；结论落到已观察子技能。
- 模式转换、开始题目和接受计划由学生明确选择；“今天先休息”是一条完整路径。
- 先保存原始作答和提示暴露，再做评分、状态计算与报告；报告必须能够回到证据。
- 当前升级方向为本机单用户服务、SQLite 持久化和三个受控角色；首选模型按现有配置为智谱 glm-5.3-flash，可替换。
- 原型与研发测试只使用合成学习材料。已有可选公网托管与隧道支持代码，不代表线上已验收或具备多用户隔离；真实学生、正式发布和真实通知须另行验证。
- 用户提供的四步引导纳入教学目标；E1受控出题已有交付与真实模型自验，互动首页/豆包TTS已有代码和启用配置；完整四步教学与语音专项验收仍未完成。多学科和全年龄覆盖保持后续愿景。

### 1.3 成功的产品体验

学生能够回答“我愿不愿意开始”“这次具体卡在哪里”“小N凭什么这样说”“下一步做多大一件事”。之后用未见同类题与跨日记录核对变化，允许出现未知、待核查、休息和题库不足。

不承诺提分、治疗、智力诊断或完整五维测量；不以聊天时长、连续打卡或宠物依赖衡量进步。

## 2 目标用户与产品目标

### 2.1 角色与使用场景

| 角色 | 核心需要 | 本版提供的价值 |
| --- | --- | --- |
| 七年级学生 | 考后不愿面对错题，想先说说 | 可聊、可休息、可自主转入看题 |
| 有具体困难的学生 | 不知道是读题、推理还是运算出问题 | 把问题缩小到有证据的子技能 |
| 已完成一次练习的学生 | 想知道自己是否真的会了 | 区分提示完成、原题重做和新题独立完成 |
| 监护人 | 理解学习目标与进度，管理必要授权 | 当前仅权限流程演示，不默认展示敏感倾诉 |
| 项目团队与验收人员 | 能复现闭环、判断能力边界 | 合成场景、版本记录、分层验证证据 |

### 2.2 目标与用户故事

G1 自主进入：作为学生，我可以先聊或休息，不会因为拒绝测评失去基本体验。

G2 具体发现：作为学生，我可以看到某次答案、使用过的帮助和对应观察，知道需要核对哪个步骤。

G3 小步行动：作为学生，我可以接受、减量、改期或暂不开始计划，今日安排与选择一致。

G4 真实回顾：作为学生，我可以查看过去报告和计划，分清旧结论、更新依据及尚不能确定的部分。

G5 数据可控：作为学生，我可以停止可选记忆、更正或删除条目，后续回复真正遵守这些选择。

G6 说清卡点：作为学生，我可以先说自己怎么想，由小N用一连串相互关联、一次一个的问题帮助定位困难，而非立刻让我接受一个能力标签。

G7 主动总结：作为学生，我可以自己复述这次学到的方法、选择下一步，并自愿表达信心是否变化；系统不替我宣称已经更有信心。

### 2.3 衡量方式

以下为后续试用的建议指标，不是现有运营结果。采集前另行确认授权、样本、观察周期和目标值；本版不启用隐性埋点。

| 指标 | 建议口径 | 用途 |
| --- | --- | --- |
| 自主进入率 | 明确选择开始的会话数 ÷ 展示学习邀请的会话数 | 判断邀请是否合适，不把休息计为失败 |
| 闭环完成率 | 已看报告且对计划作出选择的人数 ÷ 已主动开始任务的人数 | 判断流程是否接续 |
| 未见题独立表现 | 无关键帮助、首次有效作答正确的合格新题数 ÷ 合格新题尝试数 | 观察具体子技能变化，分题族报告 |
| 延迟复测结果 | 到期且学生主动完成的独立新题结果，按间隔和帮助分类 | 不与当天改题或缺席混算 |
| 证据与控制可靠性 | 报告引用可定位率、重复写入数、休息后违规邀请数 | 自动场景要求分别为100%、0、0 |

## 4 信息架构与关键用户流程

### 4.1 导航结构

| 一级区域 | 主要内容 | 关键动作 |
| --- | --- | --- |
| 小N | 欢迎、对话、看题邀请、求助入口 | 聊聊、选题、休息、恢复 |
| 探索 | 五维地图、等价列表、任务与说明 | 选择地点、明确确认、作答或暂停 |
| 今日 | 已确认计划、到期任务、预计投入 | 自主开始、减量、改期、暂停 |
| 成长 | 子技能观察、报告、历史、阶段回顾 | 展开证据、比较版本、同类新题检验 |
| 我的与设置 | 记忆、隐私、AI说明、监护演示、帮助 | 管理许可、导入旧记录、重置或重新介绍 |

### 4.2 三条主流程

考后支持：首次介绍与必要说明 → 拒绝或选择可选功能 → 小N问候 → 学生选择先聊／看题／休息 → 学生愿意后确认一道题 → 作答与提示 → 学习观察 → 自主选择计划。

五维探索：说明观察范围与可暂停 → 理解、逻辑先行 → 其余地点可选择 → 每题独立保存过程 → 报告列出已观察与待观察 → 选择下一步。自主看题入口可以直接处理具体题目，探索先行规则不扩大为全部入口的强制测评。

后续巩固：今日查看当前确认计划与到期理由 → 学生选择开始 → 核验题目是否已见 → 完成任务 → 更新证据与排程 → 查看新报告及旧版历史。题量不足时明确说明，提供原题回顾或换目标，不虚构未见题。

### 4.3 休息与恢复

休息和“现在先不看”优先于模型建议；停止任务邀请、不自动开题、不因刷新重现催促。允许继续纯聊天，由学生主动恢复学习。改期不记失败，缺席不形成能力负面证据；恢复后不堆积所有错过任务。

## 5 首次进入与综合对话需求

### FR01 首次介绍与授权 P0

说明小N的AI身份、支持范围、回答可能有误，以及必要信息的用途；收集年龄段、年级和教材偏好。基本学习进度、可选长期记忆与研究用途分开说明，后两项默认关闭。

未满14周岁路径保留监护确认演示，展示待确认、演示完成、失败、取消；不得将前端勾选称作真实身份核验。拒绝非必要功能仍可基本学习。已完成介绍后进入主页；重新介绍与清除记录是不同操作。

验收：拒绝两个可选项目后走通任务与报告；刷新保留有效选择；监护演示失败或取消不显示核验成功。

### FR02 综合聊天与意愿控制 P0

开场提供“先聊聊”“一起看一道题”“今天先休息”。小N先了解需要，一次只问一个主要问题，避免排他依赖、责备或人格评价。允许从具体错题自然邀请学生尝试；切换模式和开始题目需明确选择。

发送后有等待、取消、失败、重试与恢复状态；失败保留输入，迟到回复不得覆盖新状态。识别到休息或拒绝后先执行程序控制，不能仅靠提示词约束模型。

验收：拒绝看题、继续聊天、刷新后不出现重复邀请；正常模型回复与本地规则回复有可识别的来源状态。新增四步引导及连续卡点追问的具体要求见FR15、FR16；不能把已有聊天输入框或一条“先倾听”prompt等同于已经实现这两项。

### FR03 三种运行环境 P0

浏览器离线规则版提供明确标注的预设对话和本机演示；连接本地服务但无模型时，学习工具、数据库和规则可以真实运行；配置模型时，通过服务端调用并显示实际失败或不可用。

曾连接新版数据源后服务中断，应保留草稿与最后记录并引导重连，避免切回旧数据造成完成状态倒退。离线单文件不宣称有后台Agent。模型Key只在本机服务端配置，PRD、日志和前端产物不得包含密钥。

## 6 任务与五维学习观察需求

### FR04 一起看题与过程记录 P0

题面持续可见，支持文本步骤或选项输入，以及“我先试试”“给一点提示”“题目识别错了”“先暂停”。数学输入提供负号和括号帮助。先保存原始尝试、题目版本和当时帮助快照，再执行评分。

首次错误、后续修改、提示后完成、原题重做、未见题首次独立完成分别留存。提交后才看的提示不能追溯修改过去的帮助状态；相关聊天关键帮助或答案暴露会影响之后的独立性判断。

验收：去括号错答 → 一级提示 → 修改正确，不能显示首次独立；新题首次无帮助正确另计；双击、重试或刷新不重复新增同一尝试。

### FR05 五维与首批题库 P0

| 维度 | 首批观察子技能 | 证据边界 |
| --- | --- | --- |
| 理解 | 数学语句与条件提取 | 需要与条件含义相关的学生表达 |
| 逻辑 | 反例及前提与结论 | 选择正确不能单独证明理由已理解 |
| 计算 | 去括号负号处理、合并同类项 | 两个子技能独立记录，不推广整体计算力 |
| 建模 | 一次性费用与随数量变化的费用 | 核对式子及各项含义 |
| 空间想象 | 二维旋转与位置关系 | 方向、中心和图形明确，可普通点击 |

当前B题库覆盖6个子技能，每个有观察、同类新题、延迟题各1道，共18道核心题，另有10道有限计算补充题。每题保存稳定ID、版本、题族、先修、答案、评分标准、提示和典型错误。简单换数只能提供有限变式证据，不宣称广泛迁移；历史v1定义保留，不把旧作答自动升级为新版标准。

探索先经理解与逻辑的有效尝试，不要求答对才放行；其他题目依先修和学生选择提供。每场次累计最多打开10道不同计算题，含补充题，重复打开不增加，刷新不能重置；正常新学习日期可由服务端开启新场次。

### FR06 分层判题与观察状态 P0

客观题及支持范围内的一次式等价判断由程序执行；不执行学生输入代码，不声称支持任意证明。步骤与自然语言依据可信评分标准逐项分析，必须包含可定位原文引用。语法不支持、模型失败、引用缺失或程序与模型冲突进入“待核查”，不能强行判错。

| 新版子技能状态 | 最低含义 | 不得扩大为 |
| --- | --- | --- |
| 尚未观察 | 没有可形成结论的证据 | 能力弱或零分 |
| 需要支持 | 有具体困难证据，应展示原步骤 | 人格、智力或永久标签 |
| 提示后完成 | 该次成功前使用过关键帮助 | 独立掌握 |
| 首次独立完成 | 合格未见题首次有效作答无帮助正确 | 跨次稳定或整个维度优秀 |
| 跨次独立完成 | 默认至少2道未见题、2个可信上海日期、2个场次 | 标准化测评分或长期掌握保证 |

“待核查”“信息不足”作为证据质量说明单独呈现，不强塞入能力状态。后续困难与既有成功可以并存；空白、暂停和未完成不产生“弱”的结论。跨次阈值属于可配置产品规则，尚无测量学有效性结论。

## 7 报告与历史版本需求

### FR07 有依据的学习报告 P0

报告包含“本次发现”“观察依据”“还需要了解”“下一步可以试试”。每项结论标明事实、推断或未知，展开后可查看题面、学生原文、提示、评分依据、来源与时间。不默认给百分制能力总分、雷达排名或人格评价。

报告只描述已覆盖子技能。新增成长反馈“理解更清晰、思路更完整、信心自评”按FR17分别关联证据和学生原话，不替代五维结果，也不自动打三个成功勾。无记录时显示尚未观察，并给可选建议；不能生成确定困难或虚构题量。模型负责组织已核验事实，不能新增得分、能力结论或已完成操作。当前受控模板／索引引用方式可满足首版要求，不以自由生成长文作为必需条件。

验收：两种不同作答画像产生不同发现；每条引用定位到真实原文；无证据时不补结论；导出若提供，应保留AI来源、时间和范围说明。旧版文本导出不自动代表新版也已完成导出接线。

### FR08 报告与计划历史 P0

生成时保存不可变快照与依据版本；新证据形成新快照，历史入口显示生成时间和变化。评分更正追加修订，旧报告提示“依据已修订”并链接替代版本，不悄悄改写原始答案或过去结论。

学生确认计划形成版本事件，记录接受、减量、改期、暂不开始的动作、原因和时间。旧计划的当时内容与当前执行进度分开；旧请求或旧版本结果不得覆盖最新确认。

验收：提示后完成报告 → 新题独立报告 → 更正评分，能查看完整轨迹；服务重启后历史仍在；修订不会把原答或旧快照直接覆盖。

## 8 计划 今日与复习需求

### FR09 差异化周计划 P0

计划突出一个主要子技能目标，说明依据、任务、预计投入和安排理由。优先处理到期支持、帮助依赖或近期困难，再补证据不足和延迟检验；允许学生改选目标。无证据时只能是可选探索建议。

提示依赖、建模困难、已有跨次独立、完全无记录四种画像应有不同目标或任务，不能使用人人相同的模板再声称个性化。计划受时间预算、先修、题库和每场次计算上限约束。

当前学生端生成接口预算为1至30分钟；C底层规则可支持1至120分钟，不表示学生端已经提供该范围。无合适任务时解释原因，允许换目标、原题回顾或休息，不捏造题目。

### FR10 学生确认与今日接续 P0

| 学生选择 | 系统行为 | 今日表现 |
| --- | --- | --- |
| 接受 | 保存确认版本和任务安排 | 显示可主动开始的任务 |
| 减量 | 减少任务；单项可改为明确的短步骤回顾 | 按实际任务估时，不把完整题假称1分钟 |
| 改期 | 保存原到期时间、目标日期及修订 | 未到新日期不催促，可主动调整 |
| 暂不开始 | 暂停当前计划与任务邀请 | 可查看、无自动开题或补做压力 |

草案不能自动替换已确认计划。今日页展示当前目标、到期原因、预计投入及暂停入口；打开任务仍需学生明确动作。恢复后同一知识点合并安排，不积压成惩罚性任务清单。

### FR11 延迟复习与阶段回顾 P0

默认间隔为1、3、7、14天，从上次合格完成时起算；是待验证产品策略，不宣称最优遗忘曲线。初始无帮助正确后，四次合格检查约在第1、4、11、25天。时间存UTC，展示和“当天”判断采用Asia/Shanghai；间隔一天按24小时处理，跨零点本身不能推进阶段。

| 复习结果 | 排程原则 | 阶段变化 |
| --- | --- | --- |
| 到期、跨场次、未见题首次独立正确 | 至少相隔24小时且上海日期不同，再按下一间隔安排 | 可推进 |
| 提示／帮助后正确 | 12小时后可支持性复查 | 保持 |
| 明确错误 | 6小时后可复查，先提供具体支持 | 保持 |
| 待核查 | 24小时后再核对 | 保持，不当作确定错误 |
| 原题、同场次或间隔不足的正确 | 不早于原安排或完成后24小时 | 保持 |
| 缺席、暂停或仅查询 | 不伪造完成记录；恢复后避免堆积 | 不升级，不降能力 |

排程是“可做时间”，不代表强制提醒或必须完成。阶段回顾分别展示原题重做、提示后完成、新题独立完成和延迟检查；原题记住答案不能算新题迁移。

## 9 记忆 上传与支持需求

### FR12 必要记录与可选长期记忆 P0

必要学习记录用于恢复、判题与报告；可选长期记忆用于跨会话偏好和个人化支持，两者用途、开关与删除范围分开说明。长期记忆默认关闭，关闭后不新增、不送入后续模型上下文；已有条目仍能查看、停止使用或删除。

每条记忆展示内容、来源、时间和用途，支持更正与停用。短期情绪不默认固化为永久标签。停止、删除、过期或到复核期的条目不得再进入模型上下文；授权变化要取消相关进行中调用，不能回放旧回复。

验收：通过下一次实际出站上下文核对更正、停用与删除，而非只看页面。删偏好不篡改原始作答；更正评分依据走独立修订流程。清除全部数据明确包含新版数据库、浏览器记录和图片，服务未连接时不假称完成。

### FR13 图片选择与题目核对 P1

流程为本地图片／示例 → 真实裁剪 → 手动遮挡姓名等无关信息 → 确认处理意图 → 核对文字。遮挡写入像素，移除图片清理对应本地内容。

当前无真实OCR，必须明确“示例识别结果”，允许手动修正；任意图片不能都显示识别成功。本版不默认外发原图，若未来接OCR，应另行说明接收方、信息范围和失败路径。新学习引擎消费核对后题目的能力需另验，不能把旧上传页面存在视为已完成接线。

### FR14 求助与监护人演示 P1

出现需要现实支持的场景时，先暂停测评和催促，提供平静支持与求助入口。联系人通知保留尚未发起、等待确认、发送中、已发送、发送失败状态；当前均为本地演示。“已发送”不等于已读或已得到帮助。

提供“这个联系人可能让我不安全”分流，允许选择其他可信成年人或保护路径；不机械通知该联系人，不编造号码、机构或人工值守能力。

监护演示限授权确认、学习概览、权利申请与安全提醒状态，默认不展示敏感聊天。真实服务前需落实身份、访问控制、流程责任人与服务资源；前端切页不构成访问隔离，也不能作为合规完成证据。

## 10 Agent职责与数据要求

### 10.1 三个角色与程序主控

| 角色 | 输入与职责 | 写入边界 |
| --- | --- | --- |
| Tutor | 当前消息、公开题目、必要学习上下文与许可偏好；回应、解释、提供受控提示 | 不能暗中开题、确认计划或改能力状态 |
| Assessor | 已保存作答、可信题目和评分标准；提供逐点评分证据候选 | 不改原答、题库或学生计划 |
| PlannerReporter | 程序核验的观察、报告事实、复习与计划草案 | 不能新增事实或替学生接受计划 |
| 程序主控 | 路由、权限、确定性评分、时间、预算、先修和持久化 | 拥有可信状态更新责任，校验模型输出 |

三个角色有独立提示词版本、输入、输出结构与轨迹，可以共用模型供应商。结构化传递必要结果，避免全部聊天共享与自由递归调用。目标约束为每次学生操作最多2次专门角色委派，并满足总调用预算；单次受控循环上限4轮模型、6次工具执行。总操作预算仍须专项集成核验，不以单个循环限额替代。

工具包括查学习上下文、证据和子技能，选题、已存作答评分、分级提示、到期复习、计划草案及记忆提议。按角色白名单开放；学生／上传文字不能自授角色、提供可信答案或执行任意代码、SQL、文件与网络请求。

### 10.2 数据对象与可信关系

| 对象 | 必要内容 | 关键约束 |
| --- | --- | --- |
| 题目与版本 | 题面、子技能、题族、先修、评分标准、提示 | 浏览器公开视图不含可信答案库 |
| 学习场次与暴露 | 场次、模式、服务端时间、看题／提示／答案／聊天帮助 | 刷新不改变场次预算，历史暴露保留 |
| 原始尝试与评分 | 原文、题目版本、当时提示快照、评分与引用 | 原答不可改写，评分修订追加 |
| 子技能与报告 | 状态、依据ID、范围、未知项、证据版本 | 新状态不覆盖旧快照 |
| 计划与复习 | 草案、学生确认、到期、完成、改期和版本 | 与原始证据关联，缺席不造结果 |
| 可选记忆与授权 | 来源、用途、有效状态、更正与删除 | 进入上下文前再次校验 |
| 运行与工具轨迹 | 角色、版本、工具、状态、错误与引用 | 去敏，不能包含Key或无关隐私 |

### 10.3 存储 迁移与恢复

升级版以本机SQLite保存学习事实，浏览器保留草稿和导航恢复缓存；离线旧版仍使用本机浏览器记录。数据源状态须明确，避免双写互相覆盖。

旧记录迁移需先导出备份、预览数量与范围，再明确导入；重复去重、错误整批回滚，不自动清空旧数据。无法证实的旧时间和暴露保留未知，不能补造跨日、独立或延迟完成证据。

写操作使用幂等标识：同一请求重放不重复写入，同标识不同内容报冲突。模型超时后原始作答仍在，可按同一记录重试分析。重启后恢复场次、历史、许可与操作结果。

## 11 体验与非功能要求

### 11.1 手机体验与视觉

沿用奶油纸色、浅绿和少量暖色，原创二维小N与轻量地图。欢迎时小N可占约半屏；对话、键盘和任务展开后优先保证内容与输入。地图用于导航，答题页收起无关装饰。

支持320、390、430像素宽度及桌面；大字号、长文本与公式不横向溢出，焦点和按钮不被键盘或底栏遮挡。控件语义清楚，状态不只靠颜色；空间题有普通点击，地图有列表替代；支持减少动效。奖励为固定方法笔记等学习成果，不采用随机宝箱或断签惩罚。

### 11.2 可靠性与反馈

| 场景 | 必须行为 |
| --- | --- |
| 发送或提交 | 立即显示处理中，避免无反馈连点 |
| 网络／模型失败 | 保留输入与已保存作答，区分保存成功和分析失败 |
| 取消与迟到响应 | 停止等待；已落库记录可核对，迟到结果不覆盖新状态 |
| 服务中断 | 显示重连和数据源状态，不假造成功 |
| 题库或预算不足 | 明确原因与可选动作，不虚构题目 |
| 重置失败 | 保留原数据并提示需重试，不显示已清除 |

建议交互操作在1秒内出现反馈；这是待实测的目标，不是已完成的性能保证。模型等待使用可见状态与取消入口，超时值由服务端配置，不以短前端计时强行截断整个调用。

### 11.3 数据与发布底线

本地默认回环地址与明确来源限制；当前代码另有可选公网Origin、容器静态托管与隧道支持。数据库仍是单用户，共享网址不等于账号隔离。未查看到本次更新对公网部署的独立验收，不能直接作为多用户正式服务。真实模型会发送必要消息、题目、作答、评分依据与获准偏好，隐私说明必须与实际链路一致。

真实学生试用前需另行确认供应商的数据保存与训练政策、服务适用范围、授权与删除流程、必要保护措施和责任人。本文不替代法律评估或合规认证，也不因一次运行成功推断服务条款或套餐适用性。

### 12.2 证据层级

验收记录必须带命令、退出码、代码快照、材料类型和限制。失败保留，修复后同命令复跑；开发者自验、对上游模块的独立复核和整版独立验收分别标注。

### 12.3 后续交付顺序

第一步核对当前提交与D最终交付及地图恢复证据，按本次修改范围建立新基线；不继续把旧的两项失败当尚无后续修复，也不把旧通过视为当前所有新增功能已验收。

第二步补足教学体验缺口：按FR15至FR17建立连续引导、卡点核实、学生总结和自评证据，先完成一条有帮助记录的计算学习片段，再验证跨日新题。

| 自动宣称更有信心 | 不从正确答案/情绪语气推断信心 | 学生明确自评、可跳过及更正入口 |
| 首批题量有限 | 承认题族覆盖与耗尽 | 补充核对题目，再验未见与迁移规则 |

| 观察状态及复习策略未做教育有效性验证 | 明确为产品规则 | 确认研究／试用方案与评价口径 |

本版先采用已确认方向；指标目标值、后续试用样本、数据保存周期、题库扩展负责人和正式发布范围仍待团队确定。它们不阻塞本地合成材料闭环的完善，但不能在真实试用前被默认为已经解决。

## 14 对话式教学与新增交互需求

### 14.1 来源比较与采用边界

用户提供的新文档依据理念海报整理，重点是“情绪陪伴、主动交互、成长反馈”；原PRD给出实现、数据和验收边界。两者方向高度一致，不是两套产品。新增明确化的是四步引导、连续追问、学生收获与信心表达，而非替换原五维、证据和复习体系。

原文的“每一次对话固定四步”在本PRD中落实为完整学习片段的教学节奏。单条问候、休息、拒绝、求助或查看历史不强行走满四步。原文的“坚持不直接给答案”落实为帮助前先引导、帮助逐级且可追溯；完成后允许按学生意愿解释与核对，不能禁止一切参考解答，也不能提前泄露未见复测试题。

### FR15 四步引导与学习片段 P0新增

四步为：先聊聊接纳当下感受；继续追问定位可核实困难；一起思考给一小步支架；看见进步由学生总结并选择下一步。它们是教学阶段，不是模型自由填写的成功标签。

程序应保存学习片段、当前阶段、关联题目版本、学生意愿、当前待核实问题、已用帮助和暂停原因；只保留接续所需信息。学生能暂停、跳过总结、继续纯聊天或主动恢复。阶段切换依据实际事件，不因模型输出“已经完成”自动推进。

当前仅具备倾听prompt、任务/提示与报告基础，无上述片段状态和四步专门验收。完成标准是能实际接续一段教学，而非改四个按钮名称。

### FR16 多轮卡点澄清与分级启发 P0新增

小N应先请学生说已知条件、当前想法或尝试，再根据真实回答选择下一个问题；一次只问一个主要问题，避免同时问“概念不清还是公式不会还是从哪下手”。概念、关系、规则或步骤困难先是待核实假设，只有任务证据支持后才能形成有限观察。

至少保留当前题和最近必要的相关回答/澄清摘要，使第二轮能引用第一轮，第三轮能检查学生是否理解。不能把所有旧聊天无差别发出；关闭可选记忆后仍可按告知范围处理当前会话必要上下文。

帮助按“请复述条件或下一步想法→指向一个关系/符号→展示必要局部步骤”逐级，学生可请求更多或暂停。每一级与相关聊天帮助进入暴露事件，提示后做对不算独立。若无法判断具体卡点，应继续核实或标未知，不强行归因。

当前Tutor发送最近8条消息、必要场次/题面和许可偏好，按用户轮数选择倾听或追问；最新d3未提交代码增加两个知识点的卡点假设记录、最近判题结果与最近3条卡点摘要。它仍禁止讲题和提示，已有题目一般只有一级静态提示；尚无完整四步片段状态或多轮自适应启发。

### FR17 学生总结与三个成长反馈角度 P0新增

学习结束可邀请学生自愿回答“这次发现了什么”“下次先做哪一步”，允许简短、跳过或以后再说。保存学生原话、时间、题目与帮助依据；AI改写建议与学生确认文本分开。

成长反馈采用三种不同来源：理解更清晰需要条件/概念解释证据；思路更完整需要学生步骤或复述证据；信心变化需要学生明确自评（如更有把握、差不多、仍不确定、暂不回答）。三者不替代五维、不是分数，不因做对自动全勾选。

表扬引用实际过程。学生曾接受帮助，应写“在提示后完成并说出了关键步骤”，不能照抄示例中“完全自己推出来了”。没有总结或自评时显示未记录，不推断低信心，不把情绪变永久人格记忆。

当前有作答证据和报告历史，但无独立的学生总结、信心自评和三角度成长卡数据/页面。真实信心提高还需真人试用验证。

### FR18 根据学习情况受控生成题目 P1新增

按已有E批任务书，首版只覆盖去括号和合并同类项：读取相关证据→模型提出受控候选参数→程序独立计算校验→去重与固定版本保存→学生确认→判题/报告/复习。模型答案不能自证；仅换数字不宣称广泛迁移。

错误/不支持/取消/预算耗尽时不发布题、不丢已有记录，回到可信题库或明确稍后再试。生成不等于学生已看，真实展示与帮助仍按现有暴露机制记录；重启后不再调用模型重造原题。

复核时E1已提交，交付目录含HANDOFF/ACCEPTANCE。实施者记载101项Agent测试、2项E浏览器测试和真实GLM生成→判题→新题复习通过；真实修复轮、真实学生和长期成本未验证。本轮读取证据与当前代码，未独立复跑该完整链路。

### FR19 互动首页与豆包语音 P1新增

首页提供小N形象、对话气泡、文字输入、学习/休息选择和可控朗读；状态与真实等待/播放事件一致。用户已选择火山引擎豆包语音作为TTS，智谱仍负责现有对话与工具，二者凭据和职责分开。

先支持朗读/停止/重播及实际音频失败处理，再按独立ASR选型实现学生语音输入。麦克风须主动开启；识别文本可编辑再发送；切页/休息/取消释放音频资源。不能把TTS接通称作双向语音完成，也不能据声音推断情绪或能力。

当前已有对话/宠物首页、服务端豆包TTS/ASR适配及客户端播放/麦克风降级代码；本机预览health为TTS启用、ASR不可用。本轮没有真实音频听验、麦克风或真实设备验收，不能把适配器或health等同双向语音通过。详细方案见交接03第10节。

### FR20 扩展学科与几何示例 P2候选

附件的三角形内角和示例用于说明四步交互。现有题库没有该知识点；二维图形旋转不等于支持三角形内角和。若以后实现，需补题目/答案/解释rubric、分级帮助、同类复测及题面图示/条件核对。

示例学生在提醒内角和关系后算出60度，应如实记帮助后完成；“更有信心”由学生自己表达。小学生、高中生和多学科均为愿景，另定范围后才能列作支持项，不能由海报概述自动扩大首版。
