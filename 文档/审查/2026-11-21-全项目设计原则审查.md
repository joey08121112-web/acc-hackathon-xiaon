## 1. 总体判断

**这个项目的设计骨架是对的，问题不在骨架，在"同一件事有两套实现"和"最近两次提交没跑测试"。**

三句实话：

1. **契约与门控是真的。** `shared/learning-contracts.ts` 用 `z.strictObject` 冻结了 40+ 实体，全部拒绝未知键；程序主控（`LearningCoordinator`）、纯函数阶段机、角色工具白名单、`permissionFingerprint` 撤销即停、答案不外泄的双重比对——这些不是口号，是能逐行验证的实现。对一个黑客松作品，这个底子比大多数同年级项目扎实得多。

2. **真正在漏水的地方是"双实现"。** 前端同时存在两套进度/记忆状态（服务端 SQLite + localStorage），后端同时存在两套 agent 运行时（`ControlledRoles` 跑线上、`AgentRuntime` 被测试覆盖），学习域同时存在两套判题引擎（`plugins/assessment` 在跑、`tools/legacy` 是死代码），`src/` 与 `server/` 互相 import。**每次"两份代码不一致"都是一个潜伏的 bug 源。**

3. **最危险的不是代码风格，是三条隐私/正确性缺口**（§2），其中两条会直接违反项目自己的 PRD。

**最痛的 3 个点**：① 记忆敏感词表可被日常语句绕过，儿童身份信息会入库并每次发给智谱；② 线上登录令牌无服务端有效期、无改密吊销、聊天接口无限流；③ 测试套件在 HEAD 上是红的，且没有 CI 门禁，红灯就这么进了主干。

## 2. P0：建议优先处理的三条

### 2.1 【实测】记忆敏感词表有洞，儿童身份信息会入库并外发

**位置**：`server/free-chat/consolidate.ts:40`（`SENSITIVE`）、`:44`（`UNCERTAIN`）、`:41-48`（`evidenceLine`）

`SENSITIVE` 词表覆盖了自杀/自残、疾病、家庭矛盾、恋爱、霸凌、身份标识等六类，**但漏掉了未成年人身份信息的四种常见形态**。用源码里的正则原样复现（【实测】，`/tmp/sens_check.mjs`）：

| 学生原话 | SENSITIVE 命中 | UNCERTAIN 命中 | 结论 |
|---|---|---|---|
| `我在实验中学` | ❌ | ❌ | **校名入库** |
| `我在实验中学上学` | ✅ | ❌ | 拦下（正则要求 `在.{1,8}(中学\|小学\|学校)上学`，必须带"上学"） |
| `我上次考试考了58分` | ❌ | ❌ | **考试分数入库**（词表里 `考试/成绩/分数` 出现 0 次） |
| `我家在文昌路12号` | ❌ | ❌ | **住址入库**（只拦 `地址/住在/小区/门牌`，拦不住"路X号"） |
| `我爸妈在杭州上班` | ❌ | ❌ | **家长信息入库**（无 `爸妈/爸爸/妈妈/父母`） |
| `我养了一只橘猫` | ❌ | ❌ | 正常入库（对照组） |

命中即写入 `fc_items`，并作为档案摘要**每次对话都发给智谱**（`server/free-chat/chat.ts:37-41`）。

**这不是"洗稿绕过"**。R1–R6 报告（`文档/审查/2026-10-30-记忆治理修复-R1到R6.md:92`）诚实地承认"极端洗稿理论上存在绕过路径"，但这四条**一个字不用洗**就能过——它们是中文里描述学校/成绩/住址/家长的最普通说法。

**最小修复**：`consolidate.ts:40` 补四组词：
- 学校：`(中学|小学|初中|学校|校区)` 去掉"上学"限定
- 成绩：`考试|成绩|分数|得分|排名|满分`
- 住址：`路\d+号|号楼|\d+单元|\d+室|小区|地址`
- 家长：`爸妈|爸爸|妈妈|父母|家长`

补完把上面那张表原样写成回归断言（`server/free-chat/consolidate.test.ts` 已有 R1/R2/R3/R5 反例的写法可循）。

**附带一条**：`store.ts:48` 的 `autoRemember()` 缺省是 `1`（开），而 PRD v1.1 第 247 行 FR12 明写"**长期记忆默认关闭**"。自由聊的自动记忆在**首访无任何显式征询**就默认开启（唯一入口是 `ProfileView.tsx:383` 的开关），与自家 PRD 冲突。学习侧的记忆（`events.ts:48`）确实是默认关，问题只在自由聊这一侧。

### 2.2 【实测】线上登录令牌无服务端有效期，且没有改密接口

**位置**：`server/storage/users.ts`（`logins` 表 / `resolveLogin`）、`server/http/server.ts:64-77`

- 全仓 `grep -E "expires_at|expiresAt"` 在 `users.ts` **零命中**——登录表根本没有过期字段。`resolveLogin` 只按 `token_hash` 查表。
- cookie 的 `Max-Age=15552000`（180 天）只约束浏览器，**令牌被复制或从设备备份恢复后，服务端仍然认**。
- 认证路由只有 `status / check / register / login / logout`——**没有改密接口**，也就没有任何批量吊销手段。家长无法让已泄露的账号失效。

口令本身的存储是合格的（`users.ts:14`：`scryptSync` + 16 字节随机盐 + `timingSafeEqual`，令牌只存 `sha256`），这条不用动。

**最小修复**：`logins` 表加 `expires_at` 并在 `resolveLogin` 校验；新增 `/api/auth/password`，改密时删除该手机号全部 `logins`；设置页给一个"退出所有设备"。

### 2.3 【读码】聊天与学习接口无限流，可直接刷爆模型额度

**位置**：`server/http/server.ts`

语音侧限流是**真做了**的：ASR 20 次/分（`:139`）、TTS 30 次/分（`:159`），每用户计量。但：

- `/api/free-chat`（`:166-173`）只限制"同时一条"，**没有每分钟/每日配额**。
- `/api/learning/*`（`:187-216`）的 `generate` / `grade` / `interview` / `report` **全无配额**。唯一的额度是 `plugins/generation/config.ts:15` 的 `dailyLimit=12`（只管题目生成，不管聊天）。
- 注册只要手机号 + 自设密码、**无验证码**（`shared/auth.ts`），全局认证配额 120 次/分（`users.ts:13`）。
- `providers/config.ts:4` 的 `hedgeMs=20000` 对冲重发会让慢请求**发两次**，成本再翻倍。

**最小修复**：free-chat 加每用户每分钟 N 次 + 每日额度；learning 类接口按用户计量；hedge 只对已登录且未被限流的用户开启。

## 3. 设计原则逐条评估

### 3.1 分层与依赖方向 —— 违反

**依赖是双向的**，两个方向的证据都在：

| 反向依赖 | 位置 | 说明 |
|---|---|---|
| server → src | `server/tools/legacy.ts:1` `import { tasks, correct } from '../../src/data'` | **服务端从前端目录取题库** |
| src → server | `src/agents/useLearning.ts:3` `import type { LearningView } from '../../server/agents/learning'` | **前端类型来自服务端实现** |

第二条尤其值得警惕：`LearningView = Awaited<ReturnType<LearningCoordinator['view']>>`（`server/agents/learning.ts:473`）。**"冻结契约"只管住了 zod 校验的单个实体，没管住聚合视图 DTO**——改一下 `LearningCoordinator.view()` 的返回形状，前端类型跟着静默变，没有契约校验、没有报错。

同类还有：`server/plugins/` 反向依赖 `server/agents/` 的 prompt 与正则（6 条：`progress→prompts/reflect`、`conversation→agents/stages`、`conversation→prompts/summary`、`interview→agents/stages`、`interview→prompts/interviewer`、`learning-loop→agents/stages`），而 `agents/` 又依赖 `plugins/`（16 条）。

**建议**：`shared/` 之外新增一个 `shared/views.ts` 放聚合 DTO（`LearningView` / `ProfessionalView`），前端只依赖 `shared/`；题库从 `src/data.ts` 迁到 `shared/`；`agents/stages.ts` 与 `agents/prompts/` 下沉为 `core/` 下的纯模块，消除 plugins→agents。

### 3.2 单一真相源 —— 违反

| 状态 | 正向源 | 影子源 | 证据 |
|---|---|---|---|
| 长期记忆开关 | 服务端 `consents` | localStorage `s.longMemory` | `App.tsx:141` 双写，`:472-475` 只在**单边缺失**时对账 |
| 学习进度/作答 | 服务端 SQLite | localStorage `xiaon-progress-v1` | `App.tsx:152/264` 与 `useLearning` 并存 |
| 页面/标签导航 | `history.state` | `s.page` / `s.tab` / `station` / `modal` | `App.tsx:277-305` 四个来源互相同步 |
| 判题 | `src/domain.ts:215` `correct()` | `App.tsx:441` 又判一次 | 同一次提交判两遍 |

**记忆开关的双写有一处具体后果**（【读码】）：

```
App.tsx:1929   checked={s.longMemory}                                  ← 设置页开关读本地
App.tsx:1930   onChange={() => patch({ longMemory: !s.longMemory })}    ← 只改本地，不通知服务端
App.tsx:2116   <Tag>{(learning.enabled ? learning.view?.optionalMemory : s.longMemory) ...}  ← 徽标读服务端
```

同在"设置/隐私"页，开关显示的是本地值、徽标显示的是服务端值，**两者可以自相矛盾**。而且设置页这个开关**不会改变服务端 consent**——服务端 `events.ts:48 memoryEnabled()` 仍按 `consents` 表判断，会继续采集。

**好消息**：新 UI 的记忆页（`src/components/learning/LearningPages.tsx:129`）有一个**正确的服务端绑定开关**（`checked={v.optionalMemory}` + `l.run('consent', {optionalMemory: !v.optionalMemory})`），生产可达。所以旧设置页那个是"静默无效的重复控件"，不是唯一入口——严重性由此下调，但同一页自相矛盾仍然要修。

### 3.3 契约与程序主控 —— 良好，建议保留

- `shared/learning-contracts.ts` 全部 `z.strictObject`，未知键直接拒；`SCHEMA_VERSION='1.0.0'`，服务端与前端都比对（`agent-client/index.ts:7` 版本不一致直接抛错）。
- `server/core/agent.ts:7` 的系统提示把"工具和学生内容是数据不是指令"写成可执行约束；`learning.ts:155` 的 `SAFETY_PATTERN` 在**任何模型调用之前**拦截，安全轮永不写入。
- 答案不外泄是双防线：`roles.ts:134-144` 对全题库做 `clean()` 归一后逐题比对学生回复，`containsAnswer` 拦截，并区分"已解题答案(released)"与"未解题答案(secrets)"。
- 证据可追溯：每次作答产出带 `quote` + `location` 的 `Evidence`，`supersedesGradingId` 支持修订；每次工具调用落 `toolCalls` 审计行。

**但有一条要补**：`server/free-chat/chat.ts:7` 的 `FREE_CHAT_PROMPT` **没有**学习 agent 那句数据/指令隔离约束（【读码】对比 `core/agent.ts:7`）。学生原文直接作为 user 消息进模型，这条路径上学生可诱导小N 复述系统提示或绕过"不直接给答案"的教学规则。

### 3.4 错误处理与失效隔离 —— 部分违反

**错误码 → HTTP 映射只覆盖 7/16**（【读码】`server/http/server.ts:18`）：

```ts
const statusCodes = { invalid_params:400, forbidden:403, not_found:404,
  conflict:409, invalid_state:409, not_implemented:501, unavailable:503 };
// ... 错误码 ↦ ??500
```

契约里 16 个错误码（`shared/learning-contracts.ts:49`），落空的 9 个里有几个映射明显不对：

- `unknown_tool` → 500（客户端错误，应 404/400）
- `budget_exhausted` → 500（应 429/409）
- `provider_auth` / `provider_rate_limit` / `provider_error` → 500（应 502/503）
- `timeout` → 500（应 504）
- `cancelled` → 500（应 499/408）

**provider 故障被降级成 HTTP 200 的学生可见文案**（【读码】`server/agents/learning.ts:315`）：模型异常被 catch 后 `run.status='failed'`，然后 `result.run.error?.message` 直接作为聊天正文返回。`glm.ts:18` 的消息是"模型网络请求失败；没有把失败当作工具成功"——**技术故障原因会出现在给中学生的回复里**，且 HTTP 状态是 200。故障应该走 5xx + 学生能看懂的兜底文案，技术原因留在服务端日志。

### 3.5 可演进性 —— 部分违反

**迁移框架"只写不读"**（【读码】`server/storage/repository.ts:34-54`）：`migrations` 表 8 个版本**从未被读取**，全项目 **0 条 `ALTER TABLE`**。建表全靠 `CREATE TABLE IF NOT EXISTS` 全键循环。版本号目前只用于人看；新增 revisioned 集合时靠 `revisioned` 集合（`:20`）**人肉维护**——漏加就会静默冲突。

**双运行时**（【读码】已验证）：`server/core/agent.ts` 的 `AgentRuntime` 在 `bootstrap.ts:23` 被实例化，但**线上路径一次都没调用**——生产走 `learning.ts:176/196/313` 的 `this.roles.invoke('tutor', ...)` → `ControlledRoles`。而 `AgentRuntime` 只被 `scripts/agent/trace.ts:11`、`scripts/agent/real-smoke.ts:10` 和 `tests-agent/a/{runtime,edges,glm-config}.test.ts`（8 处断言）调用。

**含义要说准**：`AgentRuntime` 不是"完全死代码"（测试和 smoke 脚本在用），但**那批测试保护的不是线上代码路径**。`ControlledRoles` 的行为改动没有对应断言保护。

同理，`tools/legacy.ts` 的 `LegacyCatalog` / `legacySkills` / `LegacyAssessment` 在生产也是死的——`bootstrap.ts:19` 造了 `LegacyAssessment`，`agents/learning.ts:80` 立刻用 `registerAssessment` 覆盖掉它；`registry.ts:51` 的 `engine.id==='legacy-v1'` 分支线上永不触发（线上 id 是 `'assessment-rubric-v1'`）。

### 3.6 插件机制 —— 是目录约定，不是插件

（【读码】证据见后端专项）

- 全项目只有**两处**引擎注册（`bootstrap.ts:25`），**没有任何插件注册入口**。
- 12 个插件目录接入方式各异：`assessment`/`planning`/`generation` 是 class，其余 9 个是裸导出函数被 `agents/learning.ts:1-26` 静态 import。
- ctx 形态不统一：只有 `RevampContext` 与 `ProfessionalContext` 两个手写 interface（`plugins/context.ts:7,26`），插件另配 11 种自定义 Input 类型。
- **新增一个插件要改 5 处**：契约加 schema → `repository.ts` 加 `entitySchemas` → 写插件 → `learning.ts` 加 import + `perform()` → `http/server.ts` 加路由。**没有任何一处会自动发现新插件。**（原写「4 处」且附「必须同时更新 `revisioned` 集合」，两处都不准，详见更正 7）

这条不算缺陷——12 个插件还没多到需要框架。但要**显式记录成 ADR**：否则下一个人会以为"往 `server/plugins/` 扔个目录就注册好了"。

### 3.7 前端结构 —— God 组件 + 死代码

**`src/App.tsx` 2792 行，`function App()` 从 122 行到 2762 行，约 2640 行在单个函数组件里。** 职责混杂：

**其中 1140 行是生产环境永不渲染的死代码**：8 段 `!learning.enabled && s.page === ...` 门控（`:796/929/1267/1356/1474/1557/1704/1914`），而 `useLearning.ts:42` 的 `enabled = connected || activated`，生产恒为 true。

### 3.8 数据存储 —— 良好，有一处要说清

**每用户独立 SQLite 隔离是结构性的**（【读码】）：`users.ts:11` 的 `USER_ID=/^[0-9a-f]{32}$/` 白名单让路径穿越不可能；库目录 `0700`、库文件 `0600`；会话 `userId` 来自服务端 session map，客户端无法指定。

## 4. 记忆系统专项（对照 `MEMORY-DESIGN-GUIDE.md`）

### 4.1 机制分类：合格，没有偷换概念

项目里有**两套互不相通**的记忆系统，**没有**把长上下文/上下文压缩/规则文件包装成长期记忆（这三种在本项目根本不存在）：

## B. 改动带来的行为变更（上线前要知道）

1. **从未配置过的存量用户，自动记忆会变成关闭**（明确开过的保持开、明确关过的保持关）。
   已有的记忆条目仍然保留、可看可改可删。
2. **登录令牌从「一直有效」变成 30 天硬上限**；改密码会让该手机号所有设备的令牌立刻失效。
3. **未注册登录从 404「这个手机号还没注册」变成 403「手机号或密码不对」** ——
   枚举成本变高，但错误提示对用户不再那么具体（这是有意的取舍）。
4. **`/api/auth/check` 仍会明确回答「这个手机号注册过没有」** ——
   只能靠限流和时序均衡提高成本，无法消除。残余风险已在 §2 记录。
5. **自由聊的「覆盖更新」不再原地覆盖**：旧条目保留为历史，新条目另起一条。
   档案页面上看到的是新条目，历史可在导出里看到。
6. **新增导出与删除接口**：删除不可逆，没有回收站。

**更正 1（重要）：§3.7「1140 行是生产环境永不渲染的死代码」——不成立，不能删。**

原判断基于 `useLearning.ts:42` 的 `enabled = connected || activated`，推断生产环境 `connected` 恒为 true。

const [activated,setActivated] = useState(()=>!isOfflineArtifact()&&localStorage.getItem(ACTIVATED)==='true');

### F.1 【实测 · P0】局域网用 `http://` 访问时，整个应用进不去

**现象**：用 `http://<局域网IP>:5173` 打开学伴小N（队友体验、课堂演示、手机连本机都是这条路），
点「开始和小N聊」永远失败，页面停在引导页并提示「这次没有保存好，请连接后再试。你的选择还在。」

**根因**：`crypto.randomUUID()` 只在**安全上下文**里存在（https / localhost / 127.0.0.1）。
局域网用 `http://` 打开时它不在，而 `src/agent-client/index.ts` 的 `newOperationId()` 直接调它、
**没有兜底** → 抛 TypeError → 第一次写请求（`POST /api/consent`）根本没发出去。
（`src/App.tsx` 里本来有一个带兜底的 `uid()`，但**只用在本地记录 id 上，没盖到 API 的 operationId**。）

**红/绿对照实测**（Playwright 脚本，模拟局域网 = 关掉 `crypto.randomUUID`）：

| 场景 | `crypto.randomUUID` | 点「开始和小N聊」后 | `/api/consent` |
|---|---|---|---|
| A 修前 · localhost | function | 离开引导页 | 发出 |
| B 修前 · 局域网 http | undefined | **卡在引导页，报错** | **没发出** |
| A 修后 · localhost | function | 离开引导页 | 发出 |
| B 修后 · 局域网 http | undefined | **离开引导页** | **发出** |

**已修**：把兜底收进 `src/agent-client/index.ts` 的 `localId()`（与 `App.tsx` 原来的 `uid()` 同一套），
`App.tsx` 改为直接复用它（单一真相源），并新增 2 条回归用例
（`src/agent-client/local-id.test.ts`，`npm test` 24 → 26）。

**为什么之前没人发现**：Playwright 的共享助手 `basic()` 里**故意**关掉了 `crypto.randomUUID`
来模拟局域网（注释写着「Exercise the same local-ID fallback needed by plain HTTP LAN previews」）。
也就是说**这个 bug 从 spec 写下那天起就一直在**，只是 spec 同时被 UI 改版带坏了，
所有人看到的都是「找不到按钮」，没人走到那一步。

`tests/offline.spec.ts` 测的正是这个旧产物，所以它「通过」**不能证明当前 UI 的离线版可用**。
重建它需要 `npm run build:offline`，且 `public/starbrook/*`（Godot 导出）被 gitignore，
得先确认本机那份二进制还在。**本轮未重建**，列为下一轮第 5 项。

### F.4 【实测】首页已经重做成语音聊天式，旧的「看题」入口连同它的弹窗一起成了死代码

**改版后的信息架构（2026-11-21 实测四个页签）**：

| 页签 | 现在是什么 |
|---|---|
| 小N（首页） | **语音聊天式**：「正在聊的内容 / 随时接着聊 / 静音 / 开始语音 / 打字」。没有任务卡片 |
| 专业模式 | 五站探索地图（理解花园 / 逻辑小桥 / 计算工坊 / 生活集市 / 空间山丘）+ 锦囊 / 问答版 |
| 今日 | 今日小任务 + 复习队列（空态是「还没有接受计划。查看可选建议」） |
| 成长 | 我的档案 / 能力进展 / 报告与记录 |

旧 spec 依赖的三样东西**都不在了**：
- 首页没有「一起看一道题」按钮，也没有「今天先休息」；
- 底部导航从常驻改成收在「下拉或点此查看聊天记录」抽屉里；
- 页签「探索」改名叫「专业模式」。

**更关键的一处**：`modal === "start-question"` 这个「一起看一道题，好吗？」弹窗**还在渲染，
但全项目没有任何地方打开它**（`openModal("start-question")` 零调用）——它和它里面的
「我愿意，从示例题开始」一起成了**死代码**。

结果：连上服务的产品里，**看题（做示例题、提示、暂停、报告）只剩一条入口链**：
`今日 → 查看可选建议 → 接受计划 → 开始今日小任务`；离线模式另有 `题目小工坊 → 明确选择：体验原创示例题`。
**原来首页那个一键看题的入口没了**。这是改版的有意决定还是顺手改掉的，需要产品确认 ——
本轮**不擅自加回入口**（加一个按钮就是加一条产品路径）。

### F.5 【实测】修好入口后，无障碍用例当场抓出 3 条真实 WCAG AA 违规，已修

`tests/accessibility.spec.ts` 之前是 45 秒超时红；把入口和页签名接回当前 UI 后，它**跑起来了**，
并报出 3 条**真的**违规：

| 违规 | 元素 | 问题 | 状态 |
|---|---|---|---|
| `aria-hidden-focus` | `.companion-full-caption` | 容器 `aria-hidden` 了，里面的「下拉或点此查看聊天记录」按钮却仍可聚焦 | ✅ 补 `inert={compact}`（同文件 112 行本来就是 `aria-hidden` + `inert` 成对用） |
| `color-contrast` | `.profile-switch-card small` | `#6b7a67` / `#f5f7ee` = 4.21:1 < 4.5:1 | ✅ 改 `#626f5d`（≈4.9:1） |
| `color-contrast` | `.profile-disclosure` | `var(--muted)` / `#f7f9f1` = 4.29:1 < 4.5:1 | ✅ 改 `#626f5d`（≈5.0:1）——**这条是本轮 T3-1 新加的溯源展示带进来的** |
| `color-contrast` | `.free-chat-head h2` | `#6c7d68` / `#faf9f3` = 4.17:1 < 4.5:1 | ✅ 改 `#626f5d`（≈5.0:1） |

修完复跑：`tests/accessibility.spec.ts` **3.9 秒通过，0 违规**。

**这四条里有三条是既有问题**（`.profile-switch-card small`、`.companion-full-caption`、`.free-chat-head h2`），
一条是本轮引入的（`.profile-disclosure`）。
**「网没在跑，所以没人看见」在这里被完整演示了一遍**：三个页面违反 WCAG AA 对一个
面向中小学生的产品不是小事，而它们已经存在了几个月，因为回归网从 11 月起就没绿过。

### F.6 本轮 Playwright 套件的最终状态（实测，非心算）

| 项 | 数量 | 说明 |
|---|---|---|
| 原来（HEAD `331601a`） | **0 / 18 通过**，每条 45 秒超时 | 入口按钮找不到 + `newOperationId()` 在局域网模拟下抛异常 |
| 现在 | **4 / 18 通过** | 无障碍 WCAG ✅（4.9s）、01 首次进入 ✅（2.1s）、11 监护人信息申请 ✅（2.9s）、`offline.spec.ts` ✅（3.3s，测的是旧离线产物） |
| 仍失败 | **14 条** | 全部卡在「首页已重做语音聊天式」（§F.4）：旧用例走的是「首页一键看题」那条路 |

**14 条为什么本轮不一起修**：它们断言的是产品该保证什么（首页该不该有「先休息」入口、
看题该从哪进、断网重试该是什么文案），这是**产品口径**，不是能照着现有代码反推出来的实现细节。
硬改只能把断言改成「现在是什么样」，那就把回归网变成了当前实现的快照 —— **它抓不住下一次改版**。
所以本轮的做法是：把**能确定的部分**（入口、页签、抽屉、无障碍、局域网兜底）修好并跑绿，
把**需要口径的部分**如实记成待办（F.2、F.3、F.4），而不是造一批「绿但没意义」的用例。

**这一轮 Playwright 从 0 绿到 3 绿，更重要的是它开始能报真问题了** —— F.5 那三条违规就是证据。
