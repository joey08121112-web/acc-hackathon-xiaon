- **执行**：Minimax Code（会话 `mvs_5966083998f74d90b2782221e10bff92`）
- **起因**：并行会话在《模型供应商切换》§6.3 留了一条待办——

## 一、判定：`test:agent:real` = legacy 链路 ✅

### 1.1 证据链（逐条读码）

| # | 事实 | 出处 |
|---|---|---|
| 1 | `AgentRuntime` 类定义在这里 | `server/core/agent.ts:8` |
| 2 | 它在 bootstrap 里被实例化并挂到 runtime 上 | `server/bootstrap.ts:23`：`const agent=new AgentRuntime(ctx,provider,tools,events,…)` |
| 3 | **全 `server/` 目录 grep `agent.run(` / `agent.reply(` = 0 命中** | `grep -E '(^|[^.\w])agent\.(run\|reply)\(' server/` → **No matches found** |
| 4 | HTTP 层从不读 `runtime.agent` | `server/http/server.ts` 的聊天/学习路由走 `learningFor(runtime)` 与 `runtime.freeChat` |
| 5 | 生产启动时装的是 `LearningCoordinator` | `server/index.ts:28`：`createRuntime({…}); installLearning(r,{generation})` |
| 6 | 唯一调用 `r.agent.run(...)` 的**真实模型**脚本 | `scripts/agent/real-smoke.ts:10`（= `test:agent:real`） |
| 7 | 其余 `r.agent.run` / `r.agent.reply` 命中全在测试里 | `tests-agent/a/runtime.test.ts`、`tests-agent/a/edges.test.ts`、`tests-agent/a/glm-config.test.ts`（合成 provider） |

**结论**：`AgentRuntime` **没有被下线**（它还在 bootstrap 里被 new 出来），但它在**生产 HTTP 路径上是死代码**——
没有任何一条线上路由会走到它。`test:agent:real` 因此**不能**被当成"线上链路可用"的证据。

> 上一轮那句"打的是**已下线的** `AgentRuntime`"**不够准确**（它没下线，只是没被线上调用）。
> 精确说法是：**它是一条被保留下来、只被测试和这条冒烟脚本使用的旁路编排**。

### 1.2 共享什么 / 不共享什么（这是关键，别只看"打通了"）

`test:agent:real` 通过，能证明什么、不能证明什么：

**✅ 共享 → 能证明**
- 生产与它**用同一个 provider 实例路径**：`runtime.provider` = `HedgedProvider` → `GlmProvider`
  （`server/bootstrap.ts:33`、`server/providers/hedge.ts`）。
- 所以它跑通能证明：**Key 有效、鉴权头正确、协议格式对、`thinking`/`reasoning_effort` 条件注入正确、
  模型会回话、会发原生 tool call、响应解析正常**。**这部分价值是真的**——供应商切换那一轮的"最后一米"验证，
  靠的就是它。

**❌ 不共享 → 不能证明**
- **编排层完全不同**：

| | legacy（`test:agent:real` 打这条） | 生产（线上真跑这条） |
|---|---|---|
| 入口 | `AgentRuntime.run()`（`server/core/agent.ts`） | `LearningCoordinator`（`server/agents/learning.ts`）＋ `FreeChatStore`（`server/free-chat/`） |
| system prompt | `server/core/agent.ts:7` 的 `SYSTEM` 常量 | `server/agents/roles.ts` 的 `PROMPTS` / `homeTutorPrompt`；`server/free-chat/chat.ts` 的 `FREE_CHAT_PROMPT` |
| 工具集 | `this.tools.definitions('tutor')`（`ToolRegistry`） | 学习链路同源；**自由聊链路 `tools:[]`（无工具）** |
| 上下文装配 | `server/core/agent.ts:39` 自己拼 | 各插件各自的上下文/档案装配 |
| 轮数与预算 | `run.rounds<=4` / `toolExecutions<=6` | 各链路各自的实现 |

→ 所以"这条冒烟绿了"**推不出**"线上编排也正常"。它是一条**偏窄但真实**的证据。

1. **`trace.ts` 也走 legacy**（`r.agent.reply`），只是用合成 provider、无真实请求——**不构成风险，但它是第二条 legacy 路径**，

   没有别名 = `npm run` 跑不到 = 事实上没人会随手跑。**这是"真实模型冒烟存在但没被制度化"的直接原因。**

## 三、真正缺 real smoke 的：只有「自由聊」这一条

| 链路 | 线上有没有真实模型证据 | 有没有可重复的脚本 |
|---|---|---|
| 学习/评估（`LearningCoordinator`） | ✅ `test:agent:d:real`、`test:agent:e:real` | ✅ 有别名 |
| 自由聊（`server/free-chat/chat.ts:47` → `provider.complete`，**`tools:[]`**） | ✅ **有**——生产环境两次端到端都走了它（`07c45da` 部署记录） | ❌ **没有脚本** |
| 档案/记忆整理（`server/free-chat/consolidate.ts:166`） | ⚠️ 走的是 `kickConsolidation()`，**没有专门验证过** | ❌ 没有 |
| 语音 TTS/ASR | ✅ `voice-roundtrip-smoke.ts` / `tts-smoke.ts` | ⚠️ 无 npm 别名 |

**注意「自由聊」这一行的微妙之处**：
两次生产端到端（`17600000001` / `17600000002`）**确实**用真实模型打通了自由聊——但那是**临时 curl 序列**，
**没有固化成脚本**。也就是说：**证据存在，但不可复现**。下次改 provider 配置时，没人能一条命令重跑它。

这才是这个待办项的**真正价值所在**，比"改个名字"大得多。

## 四、两条路的代价对比（**用户已决定：两条都不动，比赛后再说**）

> **决定记录（2026-11-21，用户拍板）**：「都不动，比赛后再说。」
> → 本轮**零代码改动**，§一~§三 的判定与 §四 的路线对比**作为备查结论入档**，
> 不在比赛前动 `package.json` 与脚本文件名。
> → 恢复这项工作的触发条件：比赛结束、或线上需要更完整的真实模型回归证据时。
> → 决定同时记录在 [模型供应商切换 §6.3](../交接/2026-11-21-模型供应商切换-MiniMax-M3.1-Flash.md)。

### 路 A：只改名 + 消歧（最小改动）

- `package.json`：`test:agent:real` → `test:agent:legacy:real`
- `scripts/agent/real-smoke.ts` → `scripts/agent/legacy-real-smoke.ts`
- `scripts/agent/trace.ts` → 同样标 legacy（它是调试工具，改名更该）
- 文件头加一行注释：这条打的是 legacy 编排，**不是线上链路**
- **代价**：改 `package.json` + 改文件名 + 改 `scripts/agent/test.mjs` 里的引用（若引用了这两个文件）。
- **风险**：**零行为风险**（不碰任何生产代码路径）。
- **收益**：消除"后人误读成线上回归"的风险——这正是原待办的诉求。

### 路 B：补上现行链路的真实冒烟（价值更高）

新增一条打**自由聊**的真实模型冒烟，把已经跑过两次的 curl 序列固化成脚本：
- 走 `server/free-chat/chat.ts` 的**真实编排**（`FREE_CHAT_PROMPT`、无工具、档案上下文装配）
- 用 `temporaryRepository()`（内存库），**不碰生产库、不碰真实账号**
- 断言：模型回话非空、`disclosure` 正确、消息按预期落进内存库

**顺带可以一起做的（都在 `package.json` 里加别名，零新代码）**：
- `test:agent:loop:real` → `real-learning-loop.ts`
- `test:voice:roundtrip` → `voice-roundtrip-smoke.ts`
- `test:tutor:stage` → `tutor-stage-smoke.ts`

**代价**：要新写一个脚本；按项目红线 **#6**，改完必须 `test:all` 绿了才能 commit；
含代码的变更**推送给用户确认**。

### 我的建议

**路 A + 路 B 的"别名部分"一起做，路 B 的"新脚本"作为比赛前的补齐。**

理由：
1. 路 A 是**纯改名 + 一行注释**，半小时内能落，且**零风险**——先把"会误导人"这件事堵住。
2. 别名部分是**纯 `package.json` 改动**，把已经存在、已经打现行链路的真实冒烟**变得可被制度化执行**——
   这是投入产出比最高的一块，**不用写任何新逻辑**。
3. 自由聊那条新脚本值得写，但它是**新代码**，且要过 `test:all`；比赛前有更重要的事时可以缓。
