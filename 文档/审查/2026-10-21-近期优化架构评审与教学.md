## 3. E1 受控出题：架构与数据流

### 3.1 端到端流程（谁在什么时机做什么）

```
学生点击"出一道新题"（只选知识点/用途/复习项/时间预算，4 个白名单字段）
  → 程序门控 gates()：暂停、先修、探索顺序、场次 10 道计算题、场次出题上限、
    当日上限、复习是否到期、是否配置模型        [全部在任何模型调用之前]
  → 组装模型输入 modelInput()：该知识点最近 ≤6 次作答的判定/分类/提示依赖/
    错误线索/证据 ID + 白名单模板 + 难度允许集 + avoidExpressions
    （不含学生原文、不含聊天；记忆关闭时不发偏好）
  → Generator 角色（无工具、≤2 轮、60s 超时、授权指纹变化即取消）
  → validateCandidate()：zod 严格解析 → 模板白名单 → 参数整数与量级 →
    程序自己 build() 出题面/答案/提示/典型错误 → 与模型写的
    expression/answer/steps 逐项数学比对 → 内容指纹去重 →
    用现有判题器确认"可判、答案可判对、典型错误可判错"
  → 通过：写事务内再次查重 → append 不可变 TaskDefinition + GenerationRecord
  → 失败：rejected/failed/cancelled 记录 + 原因码，不发布任何题
  → 发布 ≠ 看题：学生确认后才有 exposure，之后与原题库完全同路
```

### 3.2 关键数据结构

- **`GenerationRecord`**（`shared/learning-contracts.ts`）：审计记录。只存指纹、版本三元组（promptVersion/templateVersion/validatorVersion）、候选的原因码，**不存模型原文、密钥、被拒答案**。这是"可审计但不泄露"的正确取舍。
- **`TaskDefinition`**：与静态题库同一张表同一 schema，生成题通过 `GeneratedTaskStore.published()` 从 SQLite 的 generations+tasks 读出进统一目录——没有另建一套分数或复习通路。
- **迁移 v2**（`server/storage/repository.ts`）：纯增量（新表 + `INSERT OR IGNORE INTO migrations VALUES(2)`），旧行不动。这是 SQLite 单文件库里最稳妥的迁移方式。

### 3.3 权限与异常

- 权限：generator 在 `ROLE_POLICIES` 里 `allowedTools:[]`、maxRounds 2、maxToolExecutions 1（`server/tools/registry.ts:12`）。模型试图调工具会被直接拒并触发修复轮。
- 异常路径齐全且诚实：取消/超时/暂停/重置丢弃迟到结果（epoch + paused 双检，`generation/index.ts:111-117`）；两次候选都失败 → rejected 记录原因，前端如实展示；未配置模型 → 明确提示。
- 幂等：operationId + requestFingerprint 冲突检测（`generation/index.ts:83-85`），published/rejected 为终态直接返回。

### 3.4 一个值得注意的语义瑕疵（P3）

`validator.ts:49` 把生成题的 `variantKind` 设为 `'transfer'`/`'delayed'`，只是镜像静态题库的槽位；真正的语义（same_family_numeric_variant）放在 GenerationRecord 里。代码注释说了这一点，但 TaskDefinition 里的 `variantKind:'transfer'` 仍然容易被未来读者（或未来的你）误读成"已验证的迁移学习证据"。建议后续给生成题一个独立枚举值，或至少在 schema 注释里写明。

## 4. 两阶段 Tutor 与安全门控

- **阶段由程序决定，不由模型也不由客户端决定**（`learning.ts:122`：按用户轮数 ≤1 → listen，否则 probe）。prompt 按阶段拼装（`roles.ts` 的 `tutorPrompt(stage)`）。这把"教学流程状态机"从概率性的模型行为里拿出来放进了确定性代码——正确的选择，详见 §7.2。
- 每阶段有明确的示例话术和禁止清单（不讲题、不给答案、不替学生下结论），输出仍是严格 JSON + zod 校验。
- 快捷回复（quickReplies）是"点了以后作为普通学生消息发送"，不是模型输出（`learning.ts:37` 注释明确）。
- **安全门控**（`learning.ts:31,119`）：正则关键词 → 固定回复、`safety:true`、不存储、不进模型。方向正确（这类决策绝不能交给 prompt），但正则覆盖面有限（同义改述会漏），`SAFETY_REPLY` 里的热线号码还是 TODO。对黑客松演示够用，产品化前必须由专业人士审过。**这是 P2，代码里的 TODO 已经自我声明了。**
- 一个协议层面的小松点（P3）：stage 依据的 `history` 数组是客户端拼的，客户端可以伪造轮数影响阶段选择。单用户本机场景无实害，但它属于"客户端提供的输入被当成了状态依据"这一类问题，值得知道。

## 5. 语音批（TTS/ASR/宠物交互）

### 5.1 服务端

- `server/voice/tts.ts`：豆包 TTS 2.0 单向流式接口。手写了**括号深度 + 字符串感知的 JSON 流切分器**（`jsonObjects`），任意 chunk 边界安全——这是流式解析的经典处理，写得干净。LRU 缓存 60 条。Key/音色只读服务端环境变量。
- `server/voice/asr.ts`：豆包录音文件识别极速版。`available()` 用 0.4s 静音 WAV 探测账号是否开通，正/负结果分别缓存 5min/1min——"如实报告不可用"而不是假装可用。
- HTTP 层（`server/http/server.ts:65-89`）：两个路由都在统一的安全链之内——**Origin 白名单（:44）→ 会话 Cookie（:56）→ CSRF 双提交令牌（:57）→ 请求体大小分路由限制（ASR 约 2.1MB，:65）→ 并发/频率限制（TTS 2 并发 30/min，ASR 1 并发 20/min）**。音频 base64 进来、转发一次、不落盘不记日志。

### 5.2 前端

- `src/voice/voice.ts`：**模块级单例音频播放器 + `useSyncExternalStore`**。音频是全局互斥资源（小N不能自言自语叠音），用单例状态机比 React Context 更贴合。区分 filler（短反应，可被打断）与 speech（真回复，绝不叠音）；`generation` 计数丢弃迟到播放；点击时 `unlock()` 应对浏览器自动播放策略。
- `src/voice/mic.ts`：**双引擎降级**——服务端 ASR 可用走"本地录音 → VAD 端点检测 → 重采样 16kHz WAV → 服务端识别"，否则退浏览器 SpeechRecognition，再退打字。录音只在点击后开始，页面隐藏/取消即停，迟到转写不自动发送——与 03 方案文档 §3 的承诺逐条对得上。
- `src/voice/vad.ts`：能量端点检测，纯函数 + 注入时钟，可单测（也确实测了）。校准期环境噪声估计有上限保护，防止学生开口太快被当成噪声。
- `Art.tsx` / `pet.ts` / `PetStage.tsx`：触摸分区（body/leaf/hand/belly）、长按/滑动判定的指针手势状态机、5 连戳防刷眩晕、眼神跟随用 CSS 变量驱动避免 React 重渲染、麦克风音量环同样走 CSS 变量。这些细节体现的是**前端性能意识**：高频输入（指针移动、音频电平）不进 React 状态。
- 隐私边界设计得清楚：TTS 只发小N自己的回复文字（不发学生输入），ASR 只在点击后发录音，页面上的数据去向提示与 `MODEL_DISCLOSURE`、README 三处口径一致。

### 5.3 语音批的流程问题（P2）

代码和测试都在（`tests-agent/d/voice-input.test.ts`、`voice-stage.test.ts`、`playwright.f.config.ts` + `pet-voice.spec.ts`），但 **`文档/交接/2026-10-21/交付/` 下没有 F 的 HANDOFF/ACCEPTANCE**，03 方案文档还停留在"待实施方案"状态。E 批有的证据链（基线→首次失败→修复→终态），F 批没有。这在比赛答辩和队友接手时都会成为追问点。

## 7. 关键技术方案权衡（教学重点）

### 7.1 出题：为什么是"模板 + 参数 + 程序重算"而不是自由生成

| 方案 | 安全性 | 可验证性 | 多样性 | 成本 | 结论 |
|---|---|---|---|---|---|
| A. 模型自由写题面直接给学生 | 差：题面可能错、可能带私货/注入 | 无法穷举验证 | 最好 | 低 | 否决，对未成年人产品不可接受 |
| **B. 模型选模板填参数，程序算内容（选定）** | 好：学生看到的每个字符都是程序产的 | 强：数学结构逐项比对 + 现有判题器回验 | 受限（5 个模板换数）但够 | 中 | **选择** |
| C. 纯程序随机不调模型 | 最好 | 最强 | 同 B | 最低 | 但失去"依据学生证据选难度/焦点"的自适应价值；且任务书要求验证模型链路 |

B 的本质是**把 LLM 从"内容生产者"降级为"参数提议者"**，信任边界收缩到最小。代价是题目多样性天花板低（同类换数），而代码和 README 都如实声明了"做对不代表更广泛迁移"——没有夸大能力。这个取舍链条值得原样写进你的比赛材料。

### 7.2 Tutor 阶段状态机放哪

- 放模型（在 prompt 里让它自己记阶段）：不可测、不可复现、可被学生话术带偏。否决。
- 放客户端：客户端可伪造，且换端（未来 App）就要重写。否决。
- **放服务端程序（选定）**：确定性、可单测（`tutor-stage-smoke.ts` 就是干这个的）、对所有客户端一致。

这是把"策略放服务器、机制放协议"的经典原则用在了对话流程上。

### 7.3 TTS 为什么走服务端代理而不是浏览器直连豆包

- 浏览器直连 = Key 进前端 = 泄露；且无法统一限流/审计。直接否决。
- 纯浏览器 Web Speech 合成：免费但音色与可用性不受控（国内 Chrome 连不上）。
- **服务端 Provider 抽象 + NoTts 空对象（选定）**：`ttsFromEnvironment()` 返回 `DoubaoTts` 或 `NoTts`，未配置时功能诚实隐藏（health 报 false、UI 收起）。供应商可替换，且 Key/音色/资源 ID 永不出服务器。这是 Strategy + Null Object 两个模式的组合应用。

### 7.4 ASR 双引擎

服务端豆包（质量优先）→ 浏览器 SpeechRecognition（Safari/Edge）→ 打字。每层失败都有用户可读的说明。**降级链每一级都显式告知数据去向**（ChatPanel 的 note 随 engine 变化），这是隐私工程的正确姿势。

## 10. 软件工程教学讲解：这批实现背后的知识地图

### 10.1 信任边界与输入不信任（最重要的一个）

整批改动反复出现同一个思想：**模型输出、客户端请求、供应商响应、工具结果，全都被当作不可信输入处理**。

- 模型出的题：程序重算比对（§3）
- 模型/学生内容当指令：prompt 明写"是数据不是指令"，且真正的防线在字符集正则与结构校验，不在 prompt
- 客户端 history：只用来数轮次，不据此授权任何事
- 供应商流式响应：括号深度切分器防御畸形分块

课堂上的"永远验证外部输入"在 LLM 时代升级成了"模型的输出也是外部输入"。**面试里能把 E1 讲成'我把 LLM 放进了不可信边界内'这句话，比背十道八股文值钱。**

### 10.2 幂等与恰好一次语义

`operationId` + `requestFingerprint` + append-only 仓储 + 终态短路（published/rejected 直接返回），实现了"重试不重复记录"。这是分布式系统里 exactly-once 的经典近似做法：**在单进程 SQLite 里靠同步事务就能做对，代价极低**。对照记忆点：网络重试、用户刷新、双击按钮，三条路径都会打到同一套幂等键上。

### 10.3 TOCTOU（检查时刻 ≠ 使用时刻）

§8 的 P2 就是活教材：gates 在 t0 检查限额，写入在 t1，两时刻之间状态可变。解法是把关键断言移进写事务，让"检查+使用"原子化。这个概念在选课系统、秒杀库存、订票系统里反复出现——你现在能在自己的代码里指着一个真实缺口讲它。

### 10.4 能力模型与最小权限

`ROLE_POLICIES` 每个角色一张白名单（工具集、轮数、执行次数），generator 干脆是空工具集。这等价于操作系统里的 capability / RBAC：**权限不是"我问模型要什么"，而是"我允许它要什么"**。配合授权指纹（consents+sessionEvents+memories 的哈希）在飞行中变化即 abort，做到了权限收窄的实时生效。

### 10.5 可观测性与审计设计

GenerationRecord 是"审计而不泄露"的范本：存原因码、版本三元组、指纹；不存原文。排查"为什么这道题没出出来"只需要 reasons 数组，而泄露面为零。**版本三元组（prompt/template/validator）让你能回答"这道题是哪套规则生成的"——这是模型工程里 lineage（溯源）的最小实现。**

### 10.6 Web 安全组合拳

一个页面请求要过：Host 校验 → Origin 白名单 → `sec-fetch-site` 检查 → HttpOnly+SameSite=Strict 会话 Cookie → CSRF 双提交令牌（`timingSafeEqual` 比较）→ 路由级 body 限额 → 业务级并发/频率限制。每一层各自独立失效也兜得住。建议你把这条链画成图，逐层说清"防的是什么攻击"（DNS rebinding、CSRF、跨站写、暴力耗费）。

### 10.7 前端工程三件事

1. **全局资源用单例状态机而非 React 状态**（音频播放器 + `useSyncExternalStore`）——互斥资源不适合组件树所有权模型。
2. **高频输入绕过 React**：指针跟随、麦克风电平全走 CSS 变量 + rAF，避免每秒 60 次的重渲染。
3. **浏览器平台约束的工程化**：自动播放策略（用户手势 unlock）、`AbortController` 全链路传播（fetch → 服务端 → 供应商）、迟到结果用 generation 计数丢弃。

### 10.8 音频管线小科普

MediaRecorder 出 webm/opus → `OfflineAudioContext` 重采样到 16kHz 单声道 16bit PCM → 手写 WAV 头 → base64 → 服务端校验 RIFF 头后转发。VAD 用 RMS 能量 + 环境噪声自适应阈值判端点。这条链让你理解"采样率/位深/容器格式"不再是名词解释题。

### 10.9 你应该掌握什么（按优先级）

1. **先会设计失败路径，再写成功路径**。这批代码一半以上在处理"取消/超时/迟到/未配置/超限"，这是初级与中级工程师的分水岭。
2. **schema-first 契约**：zod schema 放 `shared/`，前后端同源，配 JSON Schema 生成。这是"契约"从文档变成可执行断言的实践。
3. **测试的层次感**：单元（模板数学/校验器）→ HTTP（路由白名单）→ 浏览器（独立端口+临时库+TestClock）→ 真实供应商。以及区分"夹具写错"和"产品写错"（E 的 ACCEPTANCE 里首次失败全是夹具问题，这个诚实记录本身就是好工程）。
4. **commit 卫生**：小批量、单一主题、可回溯。当前的 P1 就是反面教材，修它只要十分钟。
5. 面向答辩的**取舍叙事**能力：§7 的三组权衡，每个都能讲"我否决了什么、为什么"。
