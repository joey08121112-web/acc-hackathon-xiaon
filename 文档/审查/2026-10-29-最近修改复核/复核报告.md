## 缺陷

### R1 · P1 · 重置成功后，旧模型结果仍会重新写入数据

位置：`outputs/xiaon/server/http/server.ts:182`、`server/free-chat/chat.ts:25`、`server/free-chat/consolidate.ts:117`。

自由聊和后台整理独立于 learning 的 `active` / `epoch`。重置只清空表，没有中止或使这两个通道的在途请求失效。自由聊在 `await provider.complete()` 后直接追加，整理在返回后直接执行操作。

HTTP 复现：发自由聊并让模拟模型等待 → 调用 `/api/learning/reset`，收到 200 和 `{cleared:true}`，确认历史为空 → 放行模型 → 旧消息及回答重新入库。另一个内存库复现证明后台整理同样会在重置后重新创建档案和 digest。

建议：给自由聊存储增加重置代次；在所有模型结果落库前核验代次，配合取消在途请求。不能只清表或只取消浏览器等待；后台整理也必须遵守同一规则。

### R2 · P1 · 关闭自动记忆不能阻止正在整理的结果写入

位置：`outputs/xiaon/server/free-chat/consolidate.ts:104`、`:117`；`server/free-chat/store.ts:48`。

开关只在调用模型前检查。整理等待中，学生可以成功关闭自动记忆；随后返回的结果仍执行 `apply()`。复现中 `autoRemember` 已是 false，档案仍新增“喜欢打篮球”。这与页面“关掉后小N 不再记新的东西”不符。

建议：开关变更应使旧整理任务失效，落库事务内重新核验开关和任务代次；关闭后又立即开启也不应让旧任务复活。开关关闭期间对话不补记的现有逻辑应保留。

### R3 · P2 · 删除保护只检查有没有新消息，没有核验是否重新提到该内容

位置：`outputs/xiaon/server/free-chat/consolidate.ts:81`。

`userLines.some(m => m.createdAt > deleted.deletedAt)` 仅要求删除后存在任意学生消息。“今天的数学题怎么做”也能放开对旧兴趣的 `add`；更早的未整理记录和删除记录仍在模型输入里。

合成复现：先聊篮球 → 删除篮球条目 → 只聊数学 → 模拟模型依据旧记录提议加回篮球 → 服务端接受。这是服务端保护失效的复现，并不代表已观测到真实模型发生该错误。

建议：操作应携带可核验的学生消息引用，服务端核验引用在删除之后、且明确支持重新记录该内容；无法证明时不自动恢复，可让学生明确确认。

### R4 · P2 · “不对，删掉”在服务器删除失败时显示成成功

位置：`outputs/xiaon/src/components/free-chat/FreeChat.tsx:26`。

点击后先从 digest 移除条目，并可能先标记整批结果已读，删除请求的失败被空 `catch` 吞掉。网络失败或服务器 503 时，学生看到条目消失，服务器却仍持有条目，后续还会用于聊天上下文。

浏览器复现：真实 FreeChat 组件配合合成 HTTP，删除接口固定返回 503；断言请求失败后条目消失且页面没有任何错误提示。脚本为 `evidence/delete-failure-ui.mjs`。

建议：删除成功后再移除和标记已读；或为乐观更新补回滚、错误反馈与重试。

### R5 · P1 · 敏感内容过滤不能支撑“身体健康不会记”的承诺

位置：`outputs/xiaon/server/free-chat/consolidate.ts:37`、`:77`、`:94`。

目前依靠提示词与有限关键词过滤。模拟模型返回 `{op:'add',kind:'about',text:'患有哮喘'}` 时，该健康信息通过格式和敏感检查，成为长期档案，随后可由 `profileBrief()` 带进后续聊天。界面却明确写“身体健康……这类不会记”。

此证据证明的是服务端接受不该接受的模型操作，未调用真实模型，不推断真实模型的出错频率。

建议：把分类排除作为单独的入档门控；无法可靠判定时跳过或交给学生确认，并补上健康、身份信息不同措辞的负例。仅增加“哮喘”一个词不能兑现完整承诺；验收前应调整绝对化文案。

### R6 · P2 · 新增原文回放后，只有旧小结的用户失去首页历史入口

位置：`outputs/xiaon/src/components/learning/home/ChatHistory.tsx:20`、`:32`。属于未提交改动。

旧库没有 `chatLog`，迁移只新增空表。新版组件在缓存聊天和原文回放都为空时直接返回 null；即使有 `summaries` 也不渲染。静态渲染复现：输入一条旧小结、空 chatLog 和空缓存，输出为空字符串。

旧小结仍保存在数据库且可从成长页查看，没有证据表明被删除；这是首页兼容性回归。

建议：按场次合并原文回放与旧小结，没有原文的旧场次继续展示已有小结，不虚构历史原文。
