# ADR-002 · 契约冻结的边界：单实体在契约内，聚合视图也在契约内

- **状态**：生效（2026-11-21 起聚合视图也进契约）
- **相关代码**：`shared/learning-contracts.ts`、`shared/views.ts`、`server/agents/learning.ts`

## 背景

`shared/learning-contracts.ts` 用 `z.strictObject` 冻结了 40+ 个实体，全部拒绝未知键 ——
这部分做得很扎实。

但它**只管住了单个实体**。聚合视图 DTO 一直没进契约：

```ts
// 2026-11-21 之前
export type LearningView = Awaited<ReturnType<LearningCoordinator['view']>>;
```

前端 `src/agents/useLearning.ts` 从服务端实现**反推**类型。后果是：

> 改一下 `LearningCoordinator.view()` 的返回形状，前端类型跟着静默变，
> **没有契约校验、没有报错**。

这正是「契约冻结」的盲区：它冻住了数据长什么样，没冻住**接口整体**长什么样。

## 决策

**聚合视图也必须有显式契约，且由服务端自己把关。**

1. 视图形状写在 `shared/views.ts`（zod schema），前端只依赖 `shared/`，不再 import `server/`。
2. 服务端出站前用**同一个 schema** 自校验（`LearningCoordinator.parseView`）：
   - 通过 → 返回校验后的数据；
   - 不通过 → 记录差异路径到服务端日志，抛 `unavailable`，**不返回未校验的数据**。
3. 改视图结构时，必须先改 `shared/views.ts` —— 这是刻意的摩擦：契约变了就该让两边同时被看见。

## 后果

- **服务端改错形状会当场炸，而不是静默流到前端。**
  这条不是推演，是实测：往 `view()` 的返回里加一个多余字段，测试套件从
  **290 全绿变成 251 过 / 39 红**（契约闸门把每一次 view 调用都拦了下来）。
- **`LearningView` 的字段必须与 `LearningCoordinator.view()` 一一对应**，
  多一个少一个都会被 `z.strictObject` 拒绝。
- 派生字段（`attempts[].classification`、`tasks[].eligible`、`reports[].basisRevised`、
  `generations[].exposed`、`learningLoops[]`）在 `shared/views.ts` 里有各自的 schema，
  与实体定义共用同一份来源，不另写一份。
- **契约文件变更要重跑 `npm run schema:agent`**：
  `shared/learning-contracts.schema.json` 是由运行时 schema 生成的产物，
  两者不一致会让 `tests-agent/a/contracts.test.ts` 变红。
