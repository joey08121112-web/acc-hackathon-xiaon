# ADR-003 · 两套记忆系统的分工：一个记事实，一个记这个人

- **状态**：生效
- **相关代码**：`server/free-chat/`（A 侧 · 自由聊档案）、`server/core/events.ts` + `shared/learning-contracts.ts`（B 侧 · 学习记录）

## 背景

项目里有两套互不相干的「记忆」，名字都叫记忆，用途完全不同：

| | A 侧 · 自由聊个人档案 | B 侧 · 学习记录与可选偏好 |
|---|---|---|
| 存哪 | `fc_*` 表（学生自己的 SQLite 文件） | learning 仓库的追加式集合 |
| 记什么 | 「有个妹妹」「喜欢打篮球」「下周有篮球赛」 | 作答、评分证据、复习计划、**可选**的辅导偏好 |
| 谁写 | 模型整理（要学生原话做证据）+ 学生自己加 | 程序事件（学生点击、判题结果） |
| 开关 | 「让小N 从聊天里记住我」（自由聊侧） | 「让小N记住我的辅导偏好」（学习侧） |
| 给模型吗 | 整理时发未整理的对话；出站时带一小段简报 | 按 `purpose` 过滤后进 Tutor 上下文 |
| 停了会怎样 | 不新增、不进上下文；已有的还能看/改/删 | 不新增、不进上下文；已有的还能停用/删除 |

审查发现两处曾经越界的地方，都已修掉：

- **A 侧原地覆盖**（违反记忆准则红线「只增不改」）：
  `chatUpdate` 直接 `UPDATE fc_items SET text=…`，旧内容被盖掉。
  现在改成**失效不删**：旧条目标 `invalidated_at` 保留（当历史看），新内容另起一条并指向旧条目。
- **B 侧曾被 A 侧代替**：A 侧的聊天状态机（`src/domain.ts` 的 `chat-send`/`chat-reply` + `replyFor`）
  是另一套「记住学生说了什么」的实现。生产路径由服务端判定并回写，
  本地那套**一次都没被 dispatch 过**，2026-11-21 删掉了。

## 决策

**两套都保留，但边界写清楚，不合并。**

理由：

1. **用途不同，生命周期不同**。A 侧是「关于这个人的小事」，会过期（近况 14 天、兴趣 60 天冷却）、
   要能被学生直接改。B 侧是「学习事实」，追加式、可追溯、判题要靠它。
   硬合并会把「学生改一句话」变成「篡改一条学习记录」。
2. **可信度不同**。A 侧的条目是**模型整理**的（有学生原话做证据，但仍可能理解错）；
   B 侧的记录是**程序写**的（学生点了什么、判题判了什么）。
   混在一起就没法区分「模型说的」和「事实」。
3. **作用域已经物理隔离**（不同表、不同文件、不同开关），这本身就是记忆准则红线第 3 条
   「写入不带作用域」的正解。

## 后果

- **两边都要能溯源**。A 侧条目带 `originThreadId` + `evidenceQuote`
  （学生问「你为什么记着这个」时，答案就是那句原话，界面会显示出来）。
  B 侧的记录本身就是证据链。
- **A 侧的 update 走失效不删**，旧版本进 `itemHistory()`，导出时一并给出。
- **开关是两个**，界面上说清各自管什么；两者互不影响。
- **任何一方都不许被另一方悄悄改写**。跨侧只允许「服务端在整理时把结论回写给前端视图」。
