# 自由聊：个人档案与记忆整理 · 实施方案

2026-10-29。自由聊以后会替代首页的综合模式（小N），所以档案、对话记录和记忆整理都围着自由聊来做。这次是重构：旧的记忆模块不迁移、不复用。旧的小N 原样保留，等替换时一起清理。

**状态（2026-10-29）**：第 1–4 步已完成并提交到 main（`2c30daf`、`3193af9`、`852a365`、`966ce1c`），第 5 步（语音和动画、替换小N）推后再做。本文已按实际做法更新；和最初方案不同的地方见文末「和最初方案的差别」。

## 原则

- **跟旧系统隔离**：新代码全部放在 `server/free-chat/` 和 `src/components/free-chat/`。不走 learning 协调器，不用 Agent 角色、旧提示词，也不用旧的 `memories` 表。
- **数据按学生隔离**：每个学生一个 SQLite 文件，沿用现有的 `UserRuntimes`。档案和对话写进这个学生自己的库，用 `fc_` 开头的新表。
- **白天只记录，空闲时再整理**：学 WorkBuddy“每晚整理当天会话”的做法。聊天时不提取记忆，回复不会变慢，也不弹确认卡。
- **学生说了算**：档案页能看、能改、能删。学生删掉的不会被自动加回来。有一个总开关「让小N 从聊天里记住我」。
- **敏感内容不进档案**：心事和情绪、家庭矛盾、身体健康、学校名字和住址等能认出身份的信息、和别人的冲突。这些只在当次对话里用。

## 数据模型（每个学生库里的新表）

| 表 | 存什么 | 关键字段 |
|---|---|---|
| `fc_messages` | 自由聊的原始对话 | id、threadId、role、content、createdAt、consolidatedAt（整理过没有） |
| `fc_threads` | 一段对话，点「重新开始」就新开一段 | id、startedAt |
| `fc_basic` | 学生自己填的基本信息，只有一行 | 怎么称呼、年级 |
| `fc_items` | 档案条目 | id、kind、text、status、source、firstMentionedAt、lastMentionedAt、mentionCount、expiresAt、editedByStudent |
| `fc_forgotten` | 学生删掉过的条目 | text、kind、deletedAt；保留 90 天 |
| `fc_runs` | 每次整理的结果 | id、ranAt、status（ok / failed / skipped）、upToRowid（整理到哪一条）、changes（这次的改动）、seenAt |
| `fc_settings` | 开关 | autoRemember，默认开 |

`fc_items.kind` 分四种：

| kind | 页面上叫 | 例子 | 怎么变化 |
|---|---|---|---|
| `about` | 关于我 | 有个妹妹、养了一只猫 | 基本不过期 |
| `interest` | 兴趣爱好 | 喜欢打篮球、在看《三体》 | 60 天没提到，就变成「以前喜欢」 |
| `recent` | 最近的事 | 下周有篮球赛 | 到 expiresAt 自动删除，默认 14 天 |
| `method` | 对我有用的方法 | 画图能帮我理解 | 基本不过期 |

- `status`：`active` 表示在玩，`past` 表示以前喜欢。
- `source`：`chat` 是小N 从聊天里记下的，`student` 是学生自己加的。
- `editedByStudent`：学生加过或改过的条目，整理时只能给它加提到次数，不能改写，也不能降温。

对话原文在整理之后保留 30 天，到期删除。重要的内容这时已经进了档案。

## 接口（都在 `/api/free-chat/` 下，不经过 `/api/learning/`）

| 接口 | 作用 |
|---|---|
| `POST /api/free-chat` | 改成只发 `{text}`。服务端从库里取当前这段对话的最近 20 条，加上档案摘要去问模型，再把这一问一答存下来 |
| `GET /api/free-chat/history` | 取当前这段对话，每次切到自由聊时用 |
| `POST /api/free-chat/new-thread` | 重新开始，新开一段对话 |
| `GET /api/free-chat/profile` | 取档案，包括基本信息、条目和开关。顺便检查要不要在后台整理 |
| `POST /api/free-chat/profile/item` | 新增、修改、删除条目，或者切换「在玩 / 以前喜欢」 |
| `POST /api/free-chat/profile/basic` | 改称呼和年级 |
| `POST /api/free-chat/settings` | 打开或关闭自动记 |
| `GET /api/free-chat/digest` | 取最近一次还没给学生看过的整理结果（只含新增和更新），以及现在是不是正在整理。顺便检查要不要在后台整理 |
| `POST /api/free-chat/digest/seen` | 学生点了「知道了」，这次结果不再显示 |
| `POST /api/free-chat/consolidate` | 立刻整理一次，不等空闲，演示用。按钮只在开发者模式里显示；接口本身不限制，每个学生同一时间只跑一次 |

「重置整个演示」也要清空所有 `fc_` 表。

## 读：回话时怎么用档案

在自由聊提示词后面加一段「关于这个同学」，服务端每次请求时现场拼出来，前端不传档案：

- 称呼和年级
- 关于我：最多 4 条
- 在玩的兴趣：最多 6 条，最近提到的排在前面
- 没过期的近况：最多 4 条
- 学习方法：最多 3 条
- 总长度控制在 600 字以内

再补一句提示：自然地用上这些信息，不要每句都提，不要说“我记得你的档案里写着”。「以前喜欢」的条目不放进去。

## 写：整理记忆

**什么时候整理**：不用定时任务挨个跑所有学生，而是在学生下次打开自由聊或档案页时检查（`GET digest` 或 `GET profile`）。如果有还没整理的对话，并且满足下面任一条件，就在后台整理：

- 最后一条消息已经过去 3 小时以上（可通过环境变量 `XIAON_FC_IDLE_MIN` 配置）；
- 最后一条消息是前一天的。

整理在后台跑，不阻塞页面，自己持有一份运行时租约，请求结束也不会被回收。每个学生同一时间只跑一个整理。自动记关掉时不整理；关着时说的话直接标成已整理，以后重新打开开关也不会补记。前端拿到「正在整理」时每 5 秒再取一次结果，最多等两分钟。

**整理的步骤**：

1. **先跑固定规则**，不用模型：
   - 近况过期的删除；
   - 兴趣 60 天没提到的改成以前喜欢。
2. **调用模型**，用一段单独的整理提示词。输入三样东西：
   - 现有条目，包括 id、kind、text、status、最近提到时间；
   - 90 天内删掉过的条目；
   - 还没整理的对话，最长 8000 字，太长就只取最近的部分。
3. **模型只能输出 JSON 操作**，最多 10 条：
   - `{op:'add',kind,text,expiresAt?}`：新增一条
   - `{op:'mention',id}`：又提到了，次数加一；如果是以前喜欢，就改回在玩
   - `{op:'update',id,text}`：内容有变化
   - `{op:'past',id}`：学生明确说过不喜欢了
4. **服务端校验后再写入**：
   - 用 zod 校验格式；
   - id 必须真实存在；
   - 学生改过的条目只允许 `mention`；
   - 删掉过的内容不能 `add`，除非学生删掉之后又在对话里主动提起；
   - 再用一个简单的敏感词表兜一次底；
   - 解析失败就这次跳过，消息仍标记为没整理，下次再试，连续 3 次失败就跳过这批对话；
   - 模型调用本身出错（限流、网络）不算失败，不记结果，下次再试；
   - 同一件事换个说法（“喜欢打篮球”和“打篮球”）算「又提到一次」，不重复新增；
   - 「又提到」会把聊天记下的「以前喜欢」改回「在玩」，学生自己改过状态的不动。
5. **记录结果**：把这次整理写进 `fc_runs`，同时把这些消息标记为已整理。

**给学生看结果**：学生下次打开自由聊，最上面出一行“我把上次聊的整理了一下：记住了「下周有篮球赛」”。每条后面带一个「不对，删掉」，看过就收起。

## 和最初方案的差别

- **档案标签没有 ×**：要先点标签再点「删掉」，防止学生手滑误删。
- **后台整理的触发点**：改在 `GET digest`（打开自由聊时前端会取）和 `GET profile`（打开档案页），不在 `GET history`。效果一样。
- **「现在整理」接口不在服务端限制开发者模式**：只是按钮放在开发者模式里；每个学生同一时间只能跑一次，最多多花一点模型调用。
- **补充**：设置页和隐私页加上了自由聊和「我的档案」的说明（对话存在哪、会整理什么、不会记什么、会发给智谱什么、怎么关）。
