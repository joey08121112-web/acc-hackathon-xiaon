## 1. 前提假设（定位相关，全部未决）

产品定位未决。以下假设只影响接入方式与文案，不影响 §3–§6 的规则域规格；定位落定后逐条复核：

- **P1 宿主**：假设挂在现有学伴小N Web 应用（React + 本地 Node 服务 + SQLite，`outputs/xiaon`）内，作为一个新活动入口。若定位为独立产品或其他宿主，§7 的接入映射失效重做，规则域规格不变。
- **P2 用户与阅读量**：§9 未指定年龄段。文字量、图标化、价格表按「能独立阅读短句的学龄儿童」假设；进入阶段无概念得分（§9.2 L239），须儿童实测校准。
- **P3 设备**：桌面/平板浏览器优先，拖放为主（§9.2 L239 拖放练习）；键盘/点选替代必须有。触屏低端机性能未测。
- **P4 语言与抽象单位**：中文；「币」「游戏水量单位」是游戏内抽象，不显示为现实货币或升数（§9.1 L225）。
- **P5 定位变化会改动的清单**：入口与家长卡措辞（§9.3 L259 给出了家长卡措辞式样）、后续核对任务的另日发放渠道（§9.2 L249）、是否需要账号/监护绑定（§9 未要求，本研究切片按现有匿名身份走）、装饰素材主题。
- **P6 规则域无关承诺**：§3 数据结构、§4 命令 API、§5 验证器骨架、§6 阶梯骨架不含任何温室常量；温室数字只出现在 `MissionDefinition.params`（§3.2）与 §5.4 的实例化验证中。第二个规则域（研究文件 §11 建议从 N2 或 L2 选）应复用同一骨架，只新增 params + 引擎判定函数 + 见证。

## 2. 总体形状

```
┌─ 渲染层（React + SVG/DOM：网格、边、试水动画、记录表）   ← 工程建议，§9 未规定技术
├─ 命令/事件层（服务端权威：幂等命令 → 事件追加 + 会话修订）
├─ 规则模型（纯 TypeScript，无 IO：合法性判定 + delivered 计算）
└─ AI 适配层（只读状态 + 按帮助级别措辞；不写世界）
```

- 规则模型与渲染分离，是研究文件 §10 L269 的要求；本规格把它落为：**同一份规则模型代码在客户端做即时反馈（乐观渲染）、在服务端做权威重算**，两边以 `stateVersion` 对齐。
- 孩子的每次操作是一个**命令**（带 `operationId` + `expectedStateVersion`），服务端事务内：校验 → 重算 → 追加 `WorldEvent` → 写 `WorldSession` 新修订。事件只记有用途的动作（对齐 §3 L38 的原则；不采集鼠标轨迹）。

### 3.1 规则域无关核心

```ts
/** 网格交点坐标。温室实例：x=0..5, y=0..3（§9.1 L223）。 */
type GridPoint = readonly [number, number];

/** 边的规范 id："x1,y1-x2,y2"，端点按字典序，保证同一条边只有一个 id。 */
type EdgeId = string;

/** 一次命令后递增；也是 WorldSession 修订键（id:r<stateVersion>，同 InterviewSession 模式）。 */
type StateVersion = number; // 正整数，从 1 起

/** 规则域引擎标识。引擎 = 纯函数集合 {validatePlacement, evaluateTrial, isObjectiveSatisfied}。 */
type RuleEngineId = 'greenhouse-water-v1'; // 第二规则域新增枚举值，不改引擎内部

/** 帮助阶梯级别。分级定义来自 §3 L36；§9.2 L243 使用 H1。 */
type HintLevel = 0 | 1 | 2 | 3 | 4;

/** 帮助类别三分：概念帮助 / 操作教学 / 无障碍支持，分开记录（§3 L36）。 */
type HelpCategory = 'concept' | 'operation' | 'accessibility';

interface MissionRef { missionId: string; missionVersion: number; }

/** 任务定义：不可变版本对象，发布后只读。由 §5 验证器通过后才可发布（INV-01）。 */
interface MissionDefinition<P = unknown> {
  readonly schemaVersion: '1.0.0';
  readonly id: string;                 // 形如 'mission-greenhouse-001'
  readonly version: number;            // 不可变版本号，与 TaskDefinition.version 同风格
  readonly templateVersion: string;    // §10 L267 要求任务带 templateVersion
  readonly ruleEngine: RuleEngineId;
  /** 规则域参数，见 §3.2。引擎代码不含这些常量（INV-02 的数据面）。 */
  readonly params: P;
  /** 对儿童可见的目标一句话 + 规则常量的可见表述（§9.1 L229 规则常量对儿童可见）。 */
  readonly goalText: string;
  readonly visibleRuleText: string;
  /** 见证解：发布前必须由程序重放验证（§9.1 L231），至少 2 条（多解，§3 L34）。 */
  readonly witnesses: readonly WitnessSolution[];
  /** H1–H4 内容模板（§6）；H0 无内容。 */
  readonly hintLadder: readonly HintTemplate[];
}

interface WitnessSolution {
  readonly label: string;              // '直线5边' / '绕行7边'
  readonly edges: readonly EdgeId[];   // 有序，首段起点=水源，末段终点=温室
  readonly expectedCost: number;
  readonly expectedDelivered: number;
}

interface HintTemplate {
  readonly level: Exclude<HintLevel, 0>;
  readonly category: HelpCategory;     // v1 只实现 concept；operation/accessibility 走同结构
  readonly text: string;               // 程序持有的模板文本；模型只能改写措辞、不能超出级别（§6）
  readonly highlight?: 'edge' | 'joint'; // H1 用：标出相关区域（§9.2 L243）
}

/** 权威世界状态（修订式，append-only，旧修订永不改写）。 */
interface WorldSession {
  readonly schemaVersion: '1.0.0';
  readonly id: string;
  readonly operationId: string;        // 创建它的命令
  readonly mission: MissionRef;
  readonly templateVersion: string;
  readonly stateVersion: StateVersion; // 修订键；每次被接受的命令 +1
  readonly status: 'building' | 'paused' | 'objective_satisfied' | 'completed'; // objective_satisfied → building 的降级转换见 §4.1（R3）
  /** 场上物件：边 → 放置记录。初始半成品也在这里（见 §3.2 initialPlacement）。 */
  readonly placed: Readonly<Record<EdgeId, Placement>>;
  readonly spentBudget: number;        // = 场上 functional 且 costPerEdge>0 的件数（§4.4 不变量）
  readonly inventoryUsed: Readonly<Record<string, number>>; // 按 pieceTypeId 计已占用库存
  readonly trialCount: number;         // 已发生试水次数；下一次试水 = trialCount+1
  /** 最近一次满足目标的试水序号；null=从未满足。由程序写（§9.2 L245）。
   *  历史事实：不随后续改动回改（R3）。「当前是否满足」以 status 为准——
   *  functional 件改动会把 status 降回 'building'（§4.1 状态机降级），
   *  objective_satisfied 事件只随 trial_run 出现（INV-06，L246「避免改坏后仍完成」）。 */
  readonly objectiveTrialSeq: number | null;
  readonly startedAt: string;          // UTC ISO
  readonly updatedAt: string;
}

interface Placement {
  readonly pieceTypeId: string;        // 'pipe_normal' | 'joint_old_leak' | 'decoration'
  readonly placedAtStateVersion: StateVersion;
  readonly placedAt: string;
}

/** 事件：只追加。信封字段对齐 §3 L38（任务/引擎/内容版本、状态版本、时间、来源）。 */
interface WorldEvent {
  readonly schemaVersion: '1.0.0';
  readonly id: string;
  readonly operationId: string;        // 触发它的命令（幂等锚点）
  readonly sessionId: string;
  readonly seq: number;                // 会话内单调递增
  readonly stateVersionAfter: StateVersion;
  readonly mission: MissionRef;
  readonly templateVersion: string;
  readonly engineVersion: string;      // 规则引擎代码版本
  readonly at: string;                 // UTC ISO
  readonly source: 'student_api';      // v1 只有学生命令；AI 不产生世界事件（§7.2）
  readonly kind:
    | 'mission_started'          // §9.2 L239；无概念得分
    | 'goal_rephrased'           // §9.2 L240，目标重述是观察
    | 'component_changed'        // 放置/拆除/换件（§9.1 L223 拆换）；payload 含前后
    | 'prediction_saved'         // §9.2 L242 预测可选；存在则锁时序
    | 'trial_run'                // §9.2 L245，由程序写
    | 'objective_satisfied'      // §9.2 L245，由程序写，只随 trial_run 出现
    | 'hint_shown'               // §9.2 L243；关联 HelpExposure
    | 'revision_saved'           // §9.2 L246 另存版本
    | 'explanation_submitted'    // §9.2 L247 反思，可跳过
    | 'mission_paused'           // §9.2 L248/249
    | 'mission_completed';
  readonly payload: WorldEventPayload; // 按 kind 判别的联合，草稿略——字段以各实体为准
}

/** 一次试水的程序判定结果。试验不耗币、可重复（§9.1 L225）。 */
interface TrialResult {
  readonly schemaVersion: '1.0.0';
  readonly id: string;
  readonly operationId: string;
  readonly sessionId: string;
  readonly trialSeq: number;           // 第几次试水（从 1 起）
  readonly at: string;
  readonly mission: MissionRef;
  readonly stateVersionAtTrial: StateVersion;
  /** 连通性判定（§9.1 L227）：false 时 delivered 无意义（不模拟不明确的分流）。 */
  readonly pathLegal: boolean;
  readonly connectedPath: readonly EdgeId[]; // 与源连通的简单路径；不合法时为实际连通前缀或空
  readonly leakCount: number;          // 路径上旧漏接头数
  readonly sourceUnits: number;        // 本次发出（温室=8）
  readonly delivered: number | null;   // pathLegal ? max(0, sourceUnits − leakLoss×leakCount) : null
  readonly spentBudgetAtTrial: number;
  readonly feedbackCode: 'delivered' | 'path_invalid'; // L227 固定文案「当前试水需要一条连续、无分支的水路」
  readonly objectiveSatisfied: boolean; // delivered===目标 && 预算≤上限 && 路径合法（§9.1 L229）
  readonly predictionId: string | null; // 指向本次试水前已存的预测；null=未预测，**不填零**（§9.2 L242）
}

/** 学生的预测。预测先于试验保存才有效；小N 只复述、不判定掌握（§9.2 L244）。 */
interface Prediction {
  readonly schemaVersion: '1.0.0';
  readonly id: string;
  readonly operationId: string;
  readonly sessionId: string;
  readonly targetTrialSeq: number;     // 预测的是第几次试水（保存时 = trialCount+1）
  readonly predictedDelivered: number; // 0..sourceUnits，整数
  readonly savedAtTrialCount: number;  // 保存时已发生的试水数，用于锁时序审计
  readonly at: string;
}

/** 帮助暴露：级别 + 类别。使用帮助不扣「人格分」、不取消游戏权利（§3 L36）。 */
interface HelpExposure {
  readonly schemaVersion: '1.0.0';
  readonly id: string;
  readonly operationId: string;
  readonly sessionId: string;
  readonly mission: MissionRef;
  readonly level: HintLevel;           // 0 也记录：孩子看过 H0 反馈但未求助的对照不在此实体，此实体 level>=1
  readonly category: HelpCategory;
  readonly hintTemplateId: string;
  readonly trialSeqContext: number;    // 暴露发生在第几次试水之后
  readonly at: string;
}

/** 作品版本：功能判定在保存时点重算并冻结，装饰不影响水量（§9.2 L246；INV-06）。 */
interface ArtifactVersion {
  readonly schemaVersion: '1.0.0';
  readonly id: string;
  readonly sessionId: string;
  readonly revision: number;           // 同会话内递增，append-only
  readonly name: string | null;        // 命名温室（§9.2 L246）
  readonly kind: 'functional' | 'decorated'; // 功能完成版本与装饰版分开（L246）
  readonly snapshot: Readonly<Record<EdgeId, Placement>>; // 冻结的场上布局
  readonly spentBudgetAtSave: number;
  readonly stateVersionAtSave: StateVersion;
  readonly objectiveTrialSeqAtSave: number | null; // 保存时点的程序判定，不继承旧判定
  readonly objectiveSatisfiedAtSave: boolean;
  readonly createdAt: string;
```

**状态机降级（INV-06 / L246 / R3）**：`status='objective_satisfied'` 时，任何 **functional** 件的 `world/place` / `world/remove`（即会改变判定输入的 `component_changed`）把 `status` 置回 `'building'`；**装饰件改动不触发**（装饰不影响水量，L246）。降级是撤回「当前态满足」的声明，不是在试水之外重算满足：不运行 `evaluateTrial`、不单独发事件（`objective_satisfied` 事件仍只随 `trial_run` 出现，§3.1），当前是否满足由下一次试水重新确认。`objectiveTrialSeq` 保留为历史事实（最近一次满足的试水序号），不回改。效果：孩子满足目标后拆掉一根管（功能性改动、未再试水）的窗口期，世界显示「搭建中」而非「完成」——正是 L246「避免改坏后仍『完成』」要防的状态。`world/save-artifact` 冻结的是保存时点判定（`objectiveSatisfiedAtSave`），不受降级影响；`paused`/`completed` 无降级路径（`paused` 下改动命令本就 `invalid_state`）。

### 4.2 幂等与过期丢弃（两条硬语义）

**幂等 `operationId`**：同 `operationId` + 请求哈希一致 → 直接回放已存结果，不重复扣币、不重复写记录、不重复发起试水（INV-04，08 L105）；同 `operationId` + 请求不一致 → `conflict`。实现复用现有三件套：内存 flight 表 + `repository.once(receipt, request, work)` 原子收据 + 哈希冲突报错（`learning.ts:86-95` `perform`；`repository.ts:77`、`repository.ts:93`）。收据键沿用 `'d-event-'+operationId` 风格。

**`stateVersion` 过期丢弃**：命令携带的 `expectedStateVersion ≠` 服务端当前 `WorldSession.stateVersion` → 整条命令丢弃，返回 `stale_state_version`，客户端刷新后重试。世界**只**按服务端序应用；旧状态上的任何结果不写入世界（INV-05，08 L106）。先例：`InterviewAnswer.expectedRevision`（`learning-contracts.ts:250`）与 `learning-loop/index.ts:87` 的 `conflict`「已更新，请刷新后继续」。取消/暂停同理：`run-trial` 提交后在响应前被暂停或中断，`perform` 的 epoch/abort 检查（`learning.ts:92-93`）保证结果不落库。

### 4.3 权威归属

- 规则计算（连通、分支/环判定、delivered、目标满足）只发生在服务端规则模型（INV-02，08 L102：世界规则/目标/币值由程序决定，LLM 不能改物理/发明物件）。客户端跑同一份纯函数做**乐观渲染**（放置即时显形、不弹对错题，L241），试水结果一律以服务端 `TrialResult` 为准。
- 模型（AI）面：只读工具（查状态、查最近试水、取当前允许的帮助级别与模板），见 §7.2。模型永不持有写命令。

### 4.4 预算与退款不变量（INV-04 的可检查表述）

任意命令序列后恒成立：

1. `spentBudget = |{e ∈ placed : pieceTypes[placed[e].pieceTypeId].cost > 0}|`（温室即场上普通管数）；
2. `spentBudget ∈ [0, budget]`，不为负；
3. 每类 `inventoryUsed[type] ≤ stockLimit`（`stockLimit=null` 跳过）；
4. 币账守恒：`累计支出 − 累计退款 = spentBudget`（= 当前场上成本，不变量 1）。每笔退款必对应此前等额的支出（普通管全额退回、拆几根退几根），故退款不创造币；等价推论：余额 `budget − spentBudget` 恒成立，且任一时刻 `budget − spentBudget = budget − 累计支出 + 累计退款`。检查实现需在命令层维护「累计支出/累计退款」两个单调计数器（只增不减），V6 在随机命令序列上逐步断言（R2 修正：v1 草稿原文 `budget − spentBudget + 累计退款 = budget − 当前场上成本` 代入不变量 1 后退化为「累计退款=0」，任一次退款后即不成立——反例见 §0.1 R2；修正形式已在 12 步含拆放序列上逐步复验，输出见 §5.3）；
5. 试水不改变 `spentBudget`（L225 试验不耗币）。

装饰：无功能、不占预算语义但**占边**；孤立装饰段不影响试水判定、但占用已购买预算的意思按 L227 原文是「孤立装饰性管段不影响试水，但占用已购买预算」——装饰 `cost=0`，故其「占用」体现为占边与占库存位，不增加 `spentBudget`。此处 §9 表述与 cost=0 定义之间的张力列为内容审核项（§9 未决问题 U3）。

### 5.1 发布门（INV-01 的实现）

`verifyMission(def: MissionDefinition): {ok: true} | {ok: false, reasons: string[]}` 作为任务发布前置门，在构建期与测试期运行；**任何一条失败即任务不发布**（08 L102：无程序可解性验证的任务不发布，找不到解或超时视为未验证）。检查项按 §9.1 L231 列举的范围组织（「见证、边相邻、库存/退款及所有参数范围」）并补齐多解与对照：

- **V2 边相邻与界内**：每条见证边两端点 `0≤x<cols, 0≤y<rows` 且曼哈顿距离=1；边 id 去重（简单路径，无重复边）。
- **V3 见证重放（从 §3.2 真实初始态，按孩子可执行的命令序列）**：初始态含 `initialPlacement`（旧接头占边、库存记已用 1、`spentBudget=0`）。按见证边序逐边重放：**该边若被初始件占据，先执行 `remove`（所有边均可拆，L223；旧接头退回库存），再执行 `place` 合法性校验（占边、库存、预算）——「先拆再放」**；初始占边在见证边集之外时保留在场上。重放终态做连通性判定「源到汇的一条简单路径、无分支/环」（L227；只检查与源连通的管线，与源不连通的孤立段不影响判定），`evaluateTrial` 复算 `delivered === expectedDelivered === 8` 且 `cost ≤ budget`（L231 两者预算均足够）。修订说明（R1）：v1 草稿原文只写「逐条执行 `place` 合法性校验」，与 §3.2 默认 `initialPlacement` 放在见证 A 直线段中段 (2,2)-(3,2) 自相矛盾——重放 `place` 该边必被「未被占」校验拒绝（node 复现：`REJECTED(edge_occupied)`），按 INV-01 默认任务不可发布；且 `WitnessSolution` 只有 `edges` 字段，纯边集无法表达「先拆再放」。本修订采「重放语义允许初始占边先拆再放」方向，不取「`WitnessSolution` 增加移除步骤」方向：拆除目标可由 `initialPlacement` 与见证边集的交集完全推导，写进数据是冗余，且不含半成品的第二规则域任务无须变更结构。修订语义已程序复验（§5.3 修订复验段）：见证 A 经一次拆除 (2,2)-(3,2) 后 5 边全过（cost=5, delivered=8）；见证 B 7 边全过，初始旧接头残留为与源不连通的孤立段、路径合法（cost=7, delivered=8）。

### 5.2 判定函数伪代码（服务端权威实现的核心）

```ts
function isLegalPath(params: GreenhouseParams, placed: Record<EdgeId, Placement>):
  { legal: boolean; path: EdgeId[] } {
  // 从 source 出发沿 placed 中 functional 的边做唯一延伸（只检查与源连通的管线，L227；
  // 与源不连通的孤立段——如见证 B 场上残留的初始旧接头——不参与判定）：
  // source 处 functional 边 >1 → 分流 → legal=false
  // 途经交点处，除去来向边后仍有 ≥2 条 functional 边可选 → 分支 → legal=false（反馈固定文案，L227）
  // 回到已访问交点 → 环 → legal=false
  // 无法继续且未到 sink → 不连通 → legal=false
  // 到达 sink 且全程每交点恰入恰出 1 条 → 简单路径，legal=true
  // （R7 注：途经交点自身恒有 2 条 functional 边——入一条出一条——故判定必须按行走式
  //  「来向之外是否还有得选」表述，不能按「交点引出 >1 条边」的字面度数实现，
  //  否则一切多边路径均被误判非法；两种实现已对照复现，见 §0.1 R7）
}
function evaluateTrial(params, placed): Pick<TrialResult,
  'pathLegal'|'connectedPath'|'leakCount'|'delivered'|'objectiveSatisfied'> {
  const p = isLegalPath(params, placed);
  if (!p.legal) return { pathLegal:false, connectedPath:p.path, leakCount:0, delivered:null, objectiveSatisfied:false };
  const leaks = p.path.filter(e => placed[e].pieceTypeId === 'joint_old_leak').length; // 最多1由库存保证（V6）
  const delivered = Math.max(0, params.sourceUnits - params.leakLossPerJoint * leaks); // L229 公式
  return { pathLegal:true, connectedPath:p.path, leakCount:leaks, delivered,
           objectiveSatisfied: delivered === params.objective.deliveredTarget /* 预算合法由命令层保证 */ };
}
```

状态机注（R3）：`evaluateTrial` 只在 `world/run-trial` 与 `world/save-artifact`（保存时点冻结判定）运行；`objective_satisfied` 的**置位**只随 `trial_run` 事件出现（§3.1）。满足态的**撤回**发生在命令层：functional 件的 place/remove 即把 `status` 降回 `'building'`（§4.1 状态机降级），不调用本节判定函数——「改动即重判」的准确含义是「改动即撤回当前声明、待下次试水重判」，不是改动时重算满足。

## 6. ④ H0–H4 提示阶梯内容框架

分级定义源自 §3 L36（H0 无教学帮助；H1 标出相关区域；H2 解释一个关系/策略；H3 局部示范；H4 完整示例），温室实例内容从 §9.2 L243–L244 与 §9.1 规则推导：

| 级 | 内容框架（温室实例） | 边界（不许做什么） | 触发与记录 |
|---|---|---|---|
| **H0** 无教学帮助 | 只有世界自身的程序反馈：试水结果（8→6）、漏水可视化、记录表。不附教学话术 | 不主动解释原因、不指出位置 | 默认级。孩子未求助时一切帮助不出现（帮助是请求制，L243「可点帮助」） |
| **H1** 标出相关区域 | 高亮当前连通水路上可疑的那一段/接头（如「看看这条管子」），配一句指向，不说原因 | 不解释漏损机制、不给改法、不替孩子操作 | `world/help level=1`；`HelpExposure{level:1}` |
| **H2** 解释一个关系/策略 | 两个可选模板：①「一次只换一个接头，其他都不动，再试一次看数字怎么变」（L243 只改一项）；②用可见规则常量解释关系：「规则是送达 = 最多(0, 8 − 2×漏接头数)，你现在有 1 个漏接头」（规则常量可见，L229） | 不指定换哪条边、不代换 | `world/help level=2`；暴露记录 |
| **H3** 局部示范 | 示范**一步**：拆下旧接头、在该边放一根普通管（在示例副本上演示这一步），然后把世界留给孩子继续 | 只示范局部一步，不连续完成整条水路；示范后目标状态不由程序代达（孩子自己换，L244） | `world/help level=3` |
| **H4** 完整示例 | 展示一条完整解（如 5 边直线）从放置到试水 8→8 的全过程，在示例世界播放，不写入孩子的世界 | 不复制进孩子世界；不宣称「照做即为掌握」 | `world/help level=4`；暴露记录，后续一切完成标记为「看过完整示例后完成」（INV-03） |

横向规则（适用所有级）：

1. **操作教学与无障碍帮助单列**（`HelpCategory: 'operation' | 'accessibility'`）：怎么拖放、字号、语音读题不占用概念阶梯，也不计入概念暴露（§3 L36）。
2. **不扣分、不取消游戏权利**：使用帮助不影响可玩性；帮助后完成与独立完成是两个**事实**标记，不是分数（§3 L36；§9.3 三分）。
3. **模型只措辞、不定级、不越级**：模型收到当前级别模板与边界说明，可以改写得像孩子的话，不可升到更高级内容、不可发明规则常量（INV-02）、不可直接修好（L243–L244 的流程顺序：先解释反馈 → H1 → 需要再给只改一项提示 → 小N 复述预测 → 孩子自己换）。
4. **停顿是邀请时机，不是判定**：停顿/「怎么又少了」只触发**是否需要帮助**的询问入口，不等于不懂（L243）。
5. H4 暴露后的对照：研究文件 §9.4 L263 提示「若看过完整示例的孩子提升同样大，优先使用便宜可靠的示例路径」——因此 H4 暴露必须可从记录中筛出（`HelpExposure.level=4` 的存在性查询）。
