## ADR-001 架构路线：程序主控 + LLM 负责语言（adopted）

- **采用**：维持现有「单一协调器 + 阶段机/程序门控 + 按需角色调用 + 受限工具」架构；游戏域按研究 05 §5 增量扩展（规则引擎为状态权威，模型只做解释与受约束语义判断）。
- **为什么**：现有实现与研究 05 五路线比较的推荐结论天然一致（`registry.ts` 的工具语义、`request_hint` 拒绝注册、程序判级等即「程序主控」实例）；决策可审计、失败可回退，适合儿童产品。
- **替代方案**：单 Agent+全量工具（越权风险）；多 Agent 协商（延迟/成本/错误放大，研究 05 明确儿童交互 P0 不采用）；LLM+游戏引擎无规则层（幻觉物件/规则）。
- **风险**：规则层过死显得机械；复杂语义仍需模型判断（保留 LLM 重述通道）。
- **如何验证**：INV-01..10 逐条对照（工作流 D 产出对照表）；E 门抽查不变量。
- **重评时机**：出现「多轮自主规划才能完成」的任务类型，或单协调器延迟成为可测瓶颈时。

## ADR-002 专业模式游戏路线：2D 网格起步，SVG/DOM 优先（proposed，待工作流 C 核证）

- **采用（拟）**：研究 04 三路线中的 C（2D 探索创造）；渲染首选 SVG/DOM（复用现有美术与 CSS 体系），动画不足时局部引入 Phaser；不引 three/Babylon。
- **为什么**：零游戏基础的现状下，C 线启动成本最低（研究 04 工时估算），且温室水路切片不需要渲染引擎；移动端 390×844 与离线单文件包约束对 3D 不友好。
- **替代方案**：A 完整 3D 沙盒（⛔ 研究明确反对首发）；B 轻体素（仅在空间学习目标有证据时专项验证，P1）。
- **风险**：SVG/DOM 动画能力上限；若未来转 B 线存在重做成本——缓解：规则模型与渲染解耦（研究 05 §6），先解耦再选渲染。
- **如何验证**：工作流 C 的选型报告（bundle 体积实测、60fps 目标、维护成本）+ D2 样机真机试玩。
- **重评时机**：C 报告结论与本拟议冲突时；或试点证据表明空间操作是核心价值时。

## ADR-003 综合模式升级方式：保留阶段机，增量加意图路由与动作协议（proposed，待工作流 B 方案）

- **采用（拟）**：不重写对话系统；在 `decideStage()` 前后增加意图分类层（八类），并给 tutor 增加动作协议字段（ANSWER/CLARIFY/PROBE/HINT 等），全部走既有「字段白名单+程序校验」管线。
- **为什么**：阶段机与字段门控是已验证资产（tests-agent 多批次覆盖）；研究 03 的协议是策略层增强，不需要推翻骨架。
- **替代方案**：全新对话引擎（推翻已验证资产，无必要）；纯提示词改造（无结构化决策，不可测）。
- **风险**：意图分类错误的坏案例；分层后延迟增加一轮——缓解：分类与回复可合并为一次调用（研究 03 接口建议即如此设计）。
- **如何验证**：B 的 60 场景测试集前后对比；错误分类样本人工评审。
- **重评时机**：测试集显示分类准确率不可接受（阈值待 B 定）。

## ADR-004 工作流治理：A–E 落盘项目级、文档自动产出、代码修改必过审批（pending 你的批准）

- **采用（拟）**：五个工作流保存至 `.zcode/workflows/`（随仓库版本化）；产物只写 `文档/` 新文件；业务代码修改一律「方案批准→实现→E 门验收」三段式。
- **为什么**：复用（按名重跑+热缓存修订）+ 可审计（确认窗+阶段图+升级提问）；与你的执行限制条款一致。
- **替代方案**：一次性内联脚本（不可复用）；全部人工主会话执行（无结构化质量门）。
- **风险**：工作流脚本与代码同步漂移——缓解：脚本引用矩阵版本号，E 门检查产物索引。
- **验证**：首跑 E 基线→A→B/C/D 全链走通。
- **重评时机**：连续两轮工作流产出质量低于主会话直做时。

## ADR-005 chatLog 对话原文保留期（pending，涉及已上线行为口径）

- **背景**：未提交的 chatLog 功能逐字保存对话且无期限（reset 才清）；研究 05 §9 建议「文字聊天默认短期（如 7 天）+ 可删除」。当前匿名试用场景下隐私暴露面有限，但口径应先定再扩量。
- **选项**：a) 维持现状（演示期简单）；b) 7 天滚动清理 + 家长/孩子可删（与研究一致，需实现清理任务）；c) 保留期跟随试用时限（30 分钟身份生命周期内全留，重置即清——与试用场景最贴切）。
- **建议**：演示期 c，正式试点前 b。
- **验证**：D4 实现删除派生清理后，E 门加双身份越权与删除演练用例。

## ADR-006 模型服务商用授权口径（pending，合规项）

- **背景**：现用 GLM Coding Plan Key（`/api/coding/paas/v4`）。研究 05 E06 指出：Coding Plan 官方限定指定工具/环境，订阅不等于儿童 App 后台调用授权。
- **建议**：黑客松评审/演示期间续用；任何「面向陌生儿童正式开放」的动作之前，确认智谱标准 API 条款、数据处理协议与账单，并重算成本模型（工作流 D 成本子代理按真实单价）。
- **重评时机**：产品从「演示」转「运营」的那一刻。
