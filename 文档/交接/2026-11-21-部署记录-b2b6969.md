### 4.1 数据在 `/data` 里的实际布局（恢复时看这里）

**不是单个 `learning.sqlite`，是"1 个身份库 + 每人一个独立库"**：

```
/data/users/
├── identities.sqlite          ← accounts(4) / identities(0) / logins(8) 三张表
├── <身份id>.sqlite            ← 每个用户一个，共 4 个，各 47 张表
├── <身份id>.sqlite-shm
├── <身份id>.sqlite-wal
└── …（每个 .sqlite 都有 shm / wal 两个伴生文件）
```

机制上：`XIAON_DB_PATH=/data/learning.sqlite`（Dockerfile 里写死）现在**只用来推导 users 目录**——
`server/index.ts` 取 `dirname(XIAON_DB_PATH)` 再拼 `users/`（可用 `XIAON_USERS_DIR` 覆盖）。
旧的共享库 `learning.sqlite` **不再被读取**，留在原处，确认无用后可自行删除。

**两个容易踩的点**：

1. 容器启动时会打印「数据库路径未检测到持久卷…请将持久卷挂载到 `/data`，并设置 `XIAON_DB_PATH=/data/learning.sqlite`」。
   这句里的 `learning.sqlite` **不是数据所在**——按提示挂 `/data` 是对的，但**不要**去备份/恢复 `learning.sqlite`，
   要搬的是整个 `/data/users/` 目录。
2. 恢复时**整个 `/data/users/` 一起搬**，只搬 4 个用户库而漏掉 `identities.sqlite`，
   会出现"学习记录在、但登录不上"（身份登记表丢了）。
3. 容器内**没有 `sqlite3` 命令行**（实测 `sqlite3: not found`）。查数据要用容器自带的 node：
   `docker exec xiaon node -e "const {DatabaseSync}=require('node:sqlite'); …"`，路径是 `/data/users/*.sqlite`。

## 6. 留给下一个人的三条硬约束

1. **`/data` 不是挂载卷**，在容器可写层里。换容器必须 `docker cp` 备份/恢复，漏一步那 4 个账号的学习记录就没了。
   要搬的是整个 `/data/users/`（身份库 + 4 个用户库，见 §4.1），不是单个 `learning.sqlite`。
2. **本机 FlClash 的 TUN 会拦掉 SSH**（TCP 通、但 sshd 收不到 banner → `Connection closed`）。
   **⚠️ 这条在 2026-11-21 15:40 之后已经改法了，别再用"关代理"那招**（见
   [部署记录 07c45da](2026-11-21-部署记录-07c45da.md) §4）。
   现在的正确做法：**`ssh -B en0`**，或在 `~/.ssh/config` 的 `Host xiaon-prod` 块里加一行
   `BindInterface en0`——**代理全程保持开启**，只有这一台服务器的流量绑到物理网卡绕开 TUN。
   这样 GitHub 推送和 SSH 可以同时用，不需要任何"先 push 再关代理"的排序 gymnastics。
3. **万一还是只能用"关代理"**（例如临时没有 `BindInterface`）：`osascript -e 'quit app "FlClash"'`
   **不够**——launchd 会自动把它拉回来，TUN 网卡 `utun9` 和 fake-ip 路由（`1 → 198.18.0.1` 等）残留，
   SSH 照样报 `Connection closed`。实测可用的停法：
   ```sh
   launchctl bootout "gui/$(id -u)/$(launchctl list | grep -i clash | awk '{print $3}')"
   pkill -f "MacOS/FlClash"; pkill -f FlClashCore
   netstat -rn -f inet | grep 198.18     # 必须无输出，才能连 SSH
   ```
   恢复：`open -a FlClash`（约 2~12 秒回）。
   **但这条是下策**：关代理期间用户整机断网，2026-11-21 用户已明确抱怨过，优先用第 2 条。
