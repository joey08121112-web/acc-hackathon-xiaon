## 1. 这次为什么是"改 env + 换容器"两件事一起做

`4befb2c` 把模型供应商改成了读环境变量。新代码的 `GLM_DEFAULTS` 默认值**本身就是 MiniMax**
（`model: MiniMax-M3.1-Flash` / `baseUrl: https://api.minimax.cn/v1` / `maxTokens: 16384` /
`thinking: ''` / `reasoningEffort: ''`），但线上 `/root/xiaon.env` 里还留着旧的
`XIAON_GLM_MODEL=glm-5.3-flash`，**会覆盖默认值**。

所以两件事必须一起做，否则会出现「线上仍连 GLM、但硬编码的 `thinking:disabled` 没了 → 变慢且根本没切到 MiniMax」，
比不部署更差。

## 2. 环境变量怎么改的（密钥纪律）

**线上 `/root/xiaon.env`（不是本机 `.env.server`，是两个文件）** 改成：

| 键 | 新值 | 来源 |
|---|---|---|
| `XIAON_GLM_API_KEY` | MiniMax 订阅 Key（`sk-cp-` 开头，125 字符） | 本机 `.env.server`（用户自己粘的） |
| `XIAON_GLM_MODEL` | `MiniMax-M3.1-Flash` | 显式写死，不依赖默认值 |
| `XIAON_GLM_BASE_URL` | `https://api.minimax.cn/v1` | 显式写死 |
| `XIAON_GLM_MAX_TOKENS` | `16384` | 显式写死（与默认值一致） |
| `XIAON_GLM_THINKING` / `XIAON_GLM_REASONING_EFFORT` | **不设置** | MiniMax 收到 `thinking.type=disabled` 会 **400**；`reasoning_effort` 降档会让需要精确索引的 `PlannerReporter` 出现「报告引用越界」 |
| `XIAON_DOUBAO_*` / `XIAON_TTS_*` / `XIAON_ASR_*` | **原样保留** | 线上原有的豆包 TTS/ASR 凭据 |

**密钥传递纪律（三条都守住了）**：

1. 密钥**不进命令行** —— 先从本机 `.env.server` 抽到 `/tmp/xiaon.newkey`（`chmod 600`），再 `scp`。
2. 密钥**不进聊天** —— 全程只出现长度与前缀，没有明文。
3. **临时文件用完即删** —— 服务器上 `rm -f /root/.xiaon.newkey`，本机 `rm -f /tmp/xiaon.newkey`。

改 env 用服务器上的 python3 读文件重写（不是 `sed` 拼命令行），旧 env 备份为
`/root/xiaon.env.bak-1121-150521`（权限 600，含旧 GLM Key，**可作回滚件**）。

## 6. 留给下一个人的两条硬约束

1. **`/data` 不是挂载卷**，在容器可写层里。换容器必须 `docker cp` 备份/恢复，漏一步那 4 个账号的学习记录就没了。
2. **本机 FlClash 的 TUN 会拦掉 SSH，但关掉它又会让 GitHub 推送断掉**（直连 github.com 是 HTTP 000 / 25 秒 0 字节）。
   **顺序必须是：先 push → 再关代理 → SSH 部署 → 部署完开回代理。**
