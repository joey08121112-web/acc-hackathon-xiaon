## 0. 一图看懂最终部署了什么

```
用户手机 --HTTPS--> cloudflared 隧道（trycloudflare.com 临时域名，systemd 常驻）
                        │ 指向 127.0.0.1:8080
                        ▼
        Docker 容器 xiaon（单 Node 进程：托管前端 dist/ + /api 后端 + SQLite）
        只绑 127.0.0.1，不暴露任何公网端口
        服务器：阿里云 ECS 免费试用（IP 8.210.88.178）
```

三个组成，全部开机自启：

| 组成 | 形态 | 自启方式 |
|---|---|---|
| 应用本体 | docker 容器 `xiaon`，镜像从源码 zip 在服务器上构建 | `--restart unless-stopped` |
| 公网入口 | cloudflared quick tunnel，systemd 服务 `xiaon-tunnel` | systemd `Restart=always` |
| 配置/数据 | `/root/xiaon.env`（密钥，600 权限）、容器内 SQLite | — |

三个关键决定（都是实测出来的，别改）：

1. **不用 Nginx/Caddy 也能上线**：Node 进程自己托管 `dist/` 和 `/api`，前端只请求同源 `/api`，一个进程搞定。（Caddy 装了，后来停用了。）
2. **公网入口走 Cloudflare quick tunnel，不走 80/443 直连**：这台服务器在阿里云「探索地域」沙盒，**境外入站被过滤，Let's Encrypt 证书验证节点连不进来，证书签不出**（实测死路，详见 §4.7）；国内域名要 ICP 备案（几周）。quick tunnel 免注册、服务器只做出站连接、自带 HTTPS，绕开全部问题。
3. **HTTPS 是硬要求**：前端用了 `crypto.randomUUID()`，裸 IP 的 http 页面直接报错。隧道天然满足。

## 3. SSH 通道是怎么打通的（最大的坑，花了一个小时）

### 症状

实例创建后 `ssh root@8.210.88.178` 直接 `Permission denied (publickey)`，而且 `ssh-copy-id` 也进不去（它需要先用密码登录一次）。用户确认**没有设过密码**。

### 原因

试用流程默认用「密钥对」认证创建实例，但**密钥对列表是空的、密码也没设**——等于服务器只认一把不存在的钥匙，谁都进不去。

### 修复（全在控制台点鼠标，约 3 分钟）

1. **导入公钥**：控制台 → 云服务器 ECS → 网络与安全 → 密钥对 → 创建密钥对 → 「**导入已有密钥对**」→ 名称 `xiaon-mac` → 粘贴 Mac 的公钥（`~/.ssh/id_ed25519.pub` 内容，`ssh-ed25519 AAAA... joey08121112@gmail.com`）。
2. **⚠️ 地域必须对**：密钥对和实例必须在**同一地域**。第一次导入到了「中国香港」地域（列表里能看到密钥对但绑不上）——实例在「华东1（杭州-探索地域）」，把顶部地域切换器切过去**重新导入了一次**才成功。
3. **绑定**：密钥对列表 → `xiaon-mac` 行「绑定密钥对」→ 勾选实例 → 确定。
4. **重启**：实例列表 → 更多 → 实例状态 → 重启（绑定密钥对必须重启才生效）。

重启完成（约 1 分钟变「运行中」）后，`ssh -o BatchMode=yes root@8.210.88.178` **15 秒内直连成功**。此后全程免密。

### 安全组

用户顺手在实例详情 → 安全组 → 配置规则 → 入方向加了 TCP 80/443 放行 `0.0.0.0/0`。**事后看这步对隧道方案不是必需的**（隧道只做出站），国内访问 80/443 确实通了，但境外（Let's Encrypt 验证节点）依然被拦——说明过滤在地域层不在安全组层。

## 4. 部署执行实录（AI 在服务器上跑的每一条命令）

以下全部由助手从 Mac 通过 `ssh root@8.210.88.178 '...'` 远程执行。按时间顺序，命令基本原样。

### 4.1 摸底（30 秒）

```sh
ssh root@8.210.88.178 '
  grep PRETTY /etc/os-release        # Ubuntu 22.04.5 LTS
  nproc; free -h | sed -n 2p         # 2 核 / 1.7Gi 内存
  df -h / | tail -1                  # 40G 盘，用了 2.9G
  docker --version                   # ❌ command not found（预装没生效）
  curl -s -o /dev/null -w "%{http_code} %{time_total}s" https://open.bigmodel.cn/
                                     # 200 0.11s —— 出站访问智谱很快，好兆头
'
```

### 4.2 加 2G 交换分区（防构建 OOM）

1.7G 内存跑 `npm ci + vite build` 很紧，先垫上：

```sh
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile >/dev/null && swapon /swapfile
echo "/swapfile none swap sw 0 0" >> /etc/fstab   # 重启后仍生效
```

### 4.3 装 Docker（第一条路失败，第二条成功）

```sh
# ❌ 失败：官方脚本 + 阿里镜像源，apt index 下载失败
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh && sh /tmp/get-docker.sh --mirror Aliyun

# ✅ 成功：Ubuntu 系统自带的 docker.io
export DEBIAN_FRONTEND=noninteractive
apt-get install -y docker.io          # 装上 29.1.3
systemctl enable --now docker
```

顺手补了 `apt-get install -y unzip`（精简版系统没带）。

### 4.4 从 Mac 传文件（部署包 + 密钥）

```sh
# Mac 上执行：
scp outputs/xiaon-cloudbase-deploy.zip root@8.210.88.178:/root/xiaon.zip   # 2.6M 源码包
scp outputs/xiaon/.env.server        root@8.210.88.178:/root/xiaon.env     # 密钥整文件直传，AI 不读内容
# 服务器上：
chmod 600 /root/xiaon.env            # 密钥文件收紧权限
```

> 部署包 = 源码树去掉 `node_modules/ dist/ .local/ .env.server`，**凭包内容即可独立构建运行**（打包后在本机验证过：解包 → docker build → 起容器 → health OK）。`.env` 只进服务器文件，不进代码、不进文档、不进聊天。

### 4.5 解压 + 构建镜像（约 3 分钟）

```sh
mkdir -p /opt/xiaon && cd /opt/xiaon && unzip -oq /root/xiaon.zip
docker build -t xiaon:latest .
# Successfully built 88c560d2de7d —— 一次过
```

镜像构建逻辑在仓库 `Dockerfile` 里（node:22-bookworm-slim → npm ci → npm run build → 单进程启动，EXPOSE 8080）。

### 4.6 第一次起容器 + 服务器内部健康检查

```sh
docker run -d --name xiaon --restart unless-stopped \
  --env-file /root/xiaon.env \
  -e XIAON_PUBLIC_ORIGIN=https://<隧道地址> \
  -p 127.0.0.1:8080:8080 \
  xiaon:latest

curl -s http://127.0.0.1:8080/api/health
# {"status":"ok","mode":"model","providerKind":"real_http","voice":{"tts":true,...}}
# mode=model = 真实 GLM 模型模式，密钥生效 ✓
```

要点：`-p 127.0.0.1:8080:8080` **只绑本机回环**，公网进不来，唯一入口是隧道。启动日志会有一条「未检测到持久卷」警告——单用户演示可接受，忽略。

### 4.7 HTTPS 尝试一：Caddy + sslip.io（失败实录，别再试）

想法：用免费域名 `8-210-88-178.sslip.io`（解析到本 IP）+ Caddy 自动签 Let's Encrypt 证书，拿到固定域名。

```sh
# 装了 Caddy、配了反代、systemd 拉起——都正常
curl -fsSL "https://caddyserver.com/api/download?os=linux&arch=amd64" -o /usr/local/bin/caddy
echo '8-210-88-178.sslip.io { reverse_proxy 127.0.0.1:8080 }' > /etc/caddy/Caddyfile
```

结果：**证书签发失败**。Caddy 日志：

```
challenge failed ... tls-alpn-01 ... "8.210.88.178: Timeout during connect (likely firewall problem)"
```

排查：从用户 Mac（国内）连 80/443 **是通的**，但 Let's Encrypt 的验证节点在境外——**探索地域过滤境外入站**，验证连不进来，证书永远签不出。结论：域名直连方案在这台沙盒机器上不可行。Caddy `systemctl stop + disable`（留存备用），切换方案。

### 4.8 HTTPS 尝试二：Cloudflare quick tunnel（成功）

原理：服务器**主动向外**连 Cloudflare 边缘节点，公网用户访问 Cloudflare 的域名，流量从隧道回来——完全不需要入站端口，也不需要证书（Cloudflare 那头自动 HTTPS）。

```sh
# 装 cloudflared（GitHub release 二进制）
curl -fsSL -o /usr/local/bin/cloudflared \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x /usr/local/bin/cloudflared     # 2026.10.3

# 写成 systemd 服务，常驻 + 断线自动重连 + 开机自启
cat > /etc/systemd/system/xiaon-tunnel.service <<'EOF'
[Unit]
Description=Xiaon Cloudflare quick tunnel
After=network.target docker.service
[Service]
ExecStart=/usr/local/bin/cloudflared tunnel --url http://127.0.0.1:8080 --no-autoupdate
Restart=always
RestartSec=5
[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now xiaon-tunnel

# 拿隧道分配的公网地址（从服务日志里抓）
journalctl -u xiaon-tunnel --no-pager | grep -oE "https://[a-z0-9-]+\.trycloudflare\.com" | head -1
# → https://committees-fibre-trend-forever.trycloudflare.com
```

### 4.9 按隧道地址重建容器

`XIAON_PUBLIC_ORIGIN` 必须和隧道地址一字不差（应用拿它做来源白名单 + cookie Secure），所以拿到地址后**重建**了一次容器（`docker rm -f xiaon` → 重跑 §4.6 的 run 命令，换成真实隧道地址）。

留了一个查询脚本 `/root/tunnel-url.sh`（内容就是上面那条 journalctl + grep），以后查当前地址一条命令。

### 4.10 外网验收（从用户 Mac 走公网，不是在服务器上 curl 自己）

```sh
U=https://committees-fibre-trend-forever.trycloudflare.com
curl -s $U/api/health          # mode=model ✓ real_http ✓ tts:true ✓
curl -s $U/ | head -c 150      # 首页 HTML ✓
curl -s -o /dev/null -w '%{http_code}' $U/plan/xxx   # SPA 回退 200 ✓
curl -s -o /dev/null -w '%{http_code}' -X POST -H 'Origin: https://evil.example' \
  -H 'Content-Type: application/json' -d '{}' $U/api/local-session   # 403 ✓
curl -sI $U/ | grep -i '^HTTP' # HTTP/2 200 ✓（HTTPS 生效）
```

最后用**手机**打开链接完整走一遍业务流程，才算验收完成。

## 5. 照做清单：把打印小店部署到同一台服务器

> 不用新开服务器。学伴小N 的容器和隧道都在跑，**不要动它们**。给打印小店起并列的第二套（端口 8081、容器名 `printshop`）。

### 5.0 前提检查（不满足先改造）

打印小店必须能打成**单 Node 进程：同时托管前端构建产物 + 后端 API，监听一个端口**（学伴小N 形态）。如果是纯静态页，加个十几行的 Express/原生 http 静态服务；如果前后端分离多进程，合并或让前端构建进后端的静态目录。

### 5.1 本机打包上传

```sh
cd <打印小店项目根目录，有 Dockerfile 的那个>
zip -rq /tmp/printshop.zip . -x "node_modules/*" -x "dist/*" -x ".env*" -x ".git/*"
scp /tmp/printshop.zip root@8.210.88.178:/root/printshop.zip
# 密钥/配置同理：整文件 scp 成 /root/printshop.env，服务器上 chmod 600
```

### 5.2 服务器：解压 + 构建

```sh
ssh root@8.210.88.178
apt-get install -y unzip docker.io   # 已装会跳过
mkdir -p /opt/printshop && unzip -oq /root/printshop.zip -d /opt/printshop
cd /opt/printshop && docker build -t printshop:latest .
```

⚠️ 服务器只有 1.7G 内存 + 2G swap，**两个项目不要同时 build**，排队来（小N 的容器不受影响，只是构建期间慢）。

### 5.3 数据卷（下单记录要持久，比小N 一步到位）

```sh
mkdir -p /opt/printshop-data
# 容器里 SQLite/数据文件路径指到 /data 下（应用支持 DB_PATH 环境变量就配；不支持就在 Dockerfile 写死 /data/）
```

### 5.4 起第二条隧道（quick tunnel 可多实例并存，各自独立域名）

```sh
cat > /etc/systemd/system/printshop-tunnel.service <<'EOF'
[Unit]
Description=printshop cloudflared quick tunnel
After=network.target docker.service
[Service]
ExecStart=/usr/local/bin/cloudflared tunnel --url http://127.0.0.1:8081 --no-autoupdate
Restart=always
RestartSec=5
[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now printshop-tunnel
sleep 8
journalctl -u printshop-tunnel --no-pager | grep -oE "https://[a-z0-9-]+\.trycloudflare\.com" | head -1
# → 记下这个地址，下一步要用
```

### 5.5 起容器（PUBLIC_ORIGIN = 隧道地址，一字不差、无末尾斜杠）

```sh
docker run -d --name printshop --restart unless-stopped \
  --env-file /root/printshop.env \
  -e PUBLIC_ORIGIN="https://<上一步的地址>" \
  -p 127.0.0.1:8081:8081 \
  -v /opt/printshop-data:/data \
  printshop:latest
curl -s http://127.0.0.1:8081/api/health   # 或打印小店自己的健康检查路径
```

（环境变量名按打印小店应用实际的支持来；`PUBLIC_ORIGIN` 语义同小N 的 `XIAON_PUBLIC_ORIGIN`——公网来源白名单。）

### 5.6 外网验收（Mac/手机走公网）

1. 手机 4G 打开 `https://<隧道地址>`，首页正常渲染；
2. **完整走一遍下单流程**：选商品 → 下单 → 刷新 → 订单还在；
3. `docker restart printshop` 后订单仍在（验证挂载卷生效）；
4. 微信里直接点链接也能打开（HTTPS + 公网域名，无特殊要求）。

### 5.7 以后更新打印小店

```sh
# 本机重打 zip → scp（同 5.1）
# 服务器：
cd /opt/printshop && docker build -t printshop:latest .
docker stop printshop && docker rm printshop
# 重跑 5.5 的 docker run（PUBLIC_ORIGIN 不变就不用改）
```

构建期间旧容器照跑，停机只有几秒；数据在挂载卷里，重建容器不丢。

## 6. 运维须知（Codex 交付前应该告诉用户的）

- **隧道重启就换 URL**。换址流程：`journalctl -u printshop-tunnel --no-pager | grep -oE "https://[a-z0-9-]+\.trycloudflare\.com" | tail -1` 拿新地址 → `docker rm -f printshop` → 按 5.5 重建（PUBLIC_ORIGIN 用新地址）→ 外网验证 → 新链接发给用户。链接发出去之前先确认隧道没重启过。
- **别再试「域名 + 80/443 直连 + Let's Encrypt」**：探索地域过滤境外入站，证书签不出，已实测死路（§4.7）。
- **两个项目的镜像别同时构建**（1.7G 内存会爆）；排队。
- **服务器时钟是 UTC**，比北京慢 8 小时，看日志时间别误判。
- **SSH 只有密钥认证**（`~/.ssh/id_ed25519`），密码进不去。
- 这是**免费试用的沙盒服务器**（额度约到 2026-11 中旬）+ quick tunnel 是临时域名：扫码体验、比赛演示没问题；打印小店若要挂**真业务、真收款**，这套只能算 demo——要升级成：正式域名（备案）+ Cloudflare named tunnel（固定域名）+ 付费服务器。
- 学伴小N 的容器 `xiaon` 和隧道 `xiaon-tunnel` **不要动**；同理小N 的更新操作也别碰 printshop 的东西。
