# E1 受控出题规则

版本：prompt `generator-e1`，模板 `e1-templates-1`，校验器 `e1-validator-1`。配置在 `outputs/xiaon/server/plugins/generation/`（`templates.ts`、`validator.ts`、`config.ts`、`prompt.ts`）。

## 1. 范围

- 只开放 `negative-brackets`（去括号负号处理）和 `like-terms`（合并同类项）。HTTP 请求的知识点字段是这两个值的枚举，其他值返回 400。
- 字母只能是 `x` 或 `a`，只用整数，不用小数、乘号或嵌套括号。
- 生成题是**同族换数变式**：`familyId=family-<知识点>`，GenerationRecord 里写 `relation=same_family_numeric_variant`。`variantKind` 只沿用题库已有的取值（练习用 `transfer`，复习用 `delayed`），不代表更广泛的迁移能力。

## 2. 白名单模板

| 模板 | 知识点 | 结构 → 程序计算的答案 | 允许难度 | 额外规则 |
|---|---|---|---|---|
| nb-basic | 去括号 | a·v − (b·v − c) → (a−b)v + c | 入门、标准 | a≠b；入门要求 a>b |
| nb-plus | 去括号 | a·v − (b·v + c) → (a−b)v − c | 标准、挑战 | a≠b |
| nb-const-first | 去括号 | k − (b·v − c) → −b·v + (k+c) | 标准、挑战 | b≥2 |
| nb-tail | 去括号 | a·v + d − (b·v − c) → (a−b)v + (d+c) | 挑战 | a≠b |
| lt-terms | 合并同类项 | 3–5 个带符号项 → Σ字母系数·v + Σ常数 | 三档 | 至少 2 个字母项和 1 个常数项；入门不允许负的字母系数 |

- 所有参数都不能为 0。绝对值上限：入门 9、标准 12、挑战 15。项数：入门 3 项、标准 4 项、挑战 4–5 项。
- 以下属于退化，一律拒绝：字母项系数合计为 0（`degenerate_variable_cancels`）；有两个以上常数且常数合计为 0（`degenerate_constant_cancels`）；没有覆盖目标环节（`not_covering_target`）。
- 预计用时：入门 2 分钟、标准 3 分钟、挑战 4 分钟。超出学生时间预算的难度不发给模型。
- 允许的难度由程序决定，依据是该知识点最近一次作答的分类：
  - 没有记录：只出入门基础题，标记为“不是诊断”。
  - 有困难或看提示后完成：入门、标准。
  - 已独立完成：标准、挑战。
  - 复习到期：入门、标准。

## 3. 校验（全部由程序完成，不靠再问一次模型）

1. **严格 schema**：拒绝未知字段；`templateId`、难度、`focus` 必须是枚举值；参数必须是 −99…99 的整数。题面、答案和步骤只允许数字、x、a、+、减号、括号和空格，所以 HTML、脚本和自然语言指令都会被 schema 拦下。整段回复最长 4000 字符，只容忍外层包一层 Markdown 代码块。
2. **模板核对**：模板必须属于请求的知识点，参数键要和模板完全一致，范围、难度和退化规则都要满足。
3. **独立计算**：程序用 `expression.ts` 中独立于判题解析器（`src/data.ts`）的受限解析器和模板公式，自己生成题面结构、答案、提示和典型错误。
4. **逐项比对模型写的内容**：
   - 题面：内容指纹必须等于程序结构的指纹（`expression_mismatch`）。
   - 答案：必须已化简，且等于程序答案（`answer_mismatch`）。
   - 每一步都必须与原式等价（`steps_invalid`）；最后一步必须化简到结果（`steps_final_mismatch`）。
   - 字母必须和声明的一致。
   - 模型写的这些文字一律不展示、不保存。
5. **判题器可用**：现有 `checkObjective` 必须判“程序答案”和“完整题面表达式”为正确、判“典型错误”为错误，否则拒绝（`grader_unsupported`）。
6. **证据引用**：`evidenceIds` 必须是本次发给模型的证据 ID 的子集（`evidence_reference_invalid`）。`focus` 必须属于该模板，并且确实被本题覆盖（例如“带负号的同类项一起合并”要求真的有负的字母项）。
7. **去重**：内容指纹是每个顶层项的多重集合，括号内的项排序，字母统一抹去。所以只改空格、换减号写法、调换项序、x 与 a 互换、换 ID，都会判为重复（`duplicate_content`）。答案相同但题目不同的不算重复。对比范围是静态题库、旧 v1 题和已发布的生成题；发布事务内会再核对一次。
8. **修复轮**：第一次被拒时，只把拒绝原因代码发回模型，最多再给 1 次机会。模型请求调用工具一律视为拒绝（`tool_call_not_allowed`），工具不会被执行。

## 4. 门控（调用模型之前）

以下任一条件不满足就不调用模型：

- 学习已暂停或休息：409。
- 去括号的先修“合并同类项”没尝试过：409。
- 探索模式下理解、逻辑两站还没做：409。
- 本场次已打开 10 道不同的计算题（生成题也计入）：`budget_exhausted`。
- 本场次已发布的生成题达到 `sessionLimit`（默认 5）：`budget_exhausted`。
- 当天调用过模型的出题次数达到 `dailyLimit`（默认 12，按上海日期）：`budget_exhausted`。
- 复习用途时，复习项必须存在、属于该知识点、处于活动状态且已到期。练习用途不能携带复习项。
- 未配置模型：503 `unavailable`，原题库照常可用。

## 5. 发给模型的数据

- 包括：知识点及名称、用途和依据、允许的难度和数值上限、时间预算、可选模板说明、该知识点最近不超过 6 次作答（attemptId、证据 ID、题面表达式、判定、分类、是否有提示、是否看过答案或聊天帮助、程序给出的错误线索）、到期复习的阶段和时间、需要避开的已有题面（公开题面）、许可偏好。
- **不包括**：学生原始作答文字、聊天、其他知识点、参考答案或 rubric、被拒候选。可选记忆关闭时偏好为空数组（测试已核对实际出站请求）。

## 6. 持久化与状态

- 已发布的生成题：一条 `TaskDefinition`，ID 为 `gen-<知识点>-<内容指纹前 16 位>`、version 2，保存在 SQLite 的 `tasks`，不可覆盖。
- `GenerationRecord` 保存在新表 `generations`，字段包括：操作 ID、请求指纹、模型 ID、prompt/模板/校验器版本、证据 revision、相关证据和作答 ID、每轮候选（模板、难度、参数指纹、内容指纹、拒绝原因代码）、发布的 taskId/version、所针对的环节、族与来源题、运行 ID、失败原因、可信时间。
- 不保存 Key、请求头、推理内容、模型原文或被拒候选的答案。
- 题目状态分为：候选（`candidates[]`）、已拒绝（`rejected`）、已发布（`published`）、失败或取消（`failed`/`cancelled`）、已暴露（由真实的 task 暴露事件推出，学习视图里的 `exposed` 字段）。
- 统一题目目录 `AssessmentCatalog` 由静态题加上“有已发布记录的生成题”组成。判题、状态、工具、页面、复习都读这一个目录。重启后直接从 SQLite 读取，不会再调用模型。
- 重复的 operationId 返回同一结果；同一个 ID 换了请求内容返回 409。并发请求由现有的单操作锁拒绝。
- 重置会清空 `generations`、`tasks` 和其他所有表，目录缓存以“重置代数 + revision”为键，重置后的旧题不会复活。

## 7. 已知限制

- 学习视图和工具的候选列表上限是 100 道（静态题占 28 道），按默认限额很难触到，但长期使用没有分页。
- 只有一个数值模板族。参数的教学质量、题目难度与学生真实水平是否匹配，都没有经过真实学生验证。
- 两次真实运行共 3 次真实生成，都在第一轮通过；“修复轮”的真实行为没有观察到，只由合成模型覆盖。
