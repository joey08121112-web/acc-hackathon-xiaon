## 5. 已知差异与风险

### 5.1 思考深度档位：有真实取舍，不能只看一个指标

实测（同一脚本 `npm run test:agent:real`，各 6 次）：

| 档位 | 严格冒烟 | 真实三角色验收（`d:real`） |
|---|---|---|
| 不发 `reasoning_effort`（服务端默认 max） | 3/6 通过；失败样本都是 4 轮模型预算 + 6 次工具用满（`budget_exhausted`） | 2/2 `VERIFIED`（含 planner `completed`） |
| `XIAON_GLM_REASONING_EFFORT=medium` | 6/6 通过 | planner 失败 1 次：`provider_error 报告引用越界`（模型输出的 `statementIndexes` 越出报告范围） |

结论：**默认保持不发 `reasoning_effort`**（即 MiniMax 默认 max）。降档能消掉旧链路的工具空转，但会让 PlannerReporter 这类要精确索引的结构化输出更容易出错——这是真实链路，不能为了一条冒烟脚本去降档。若要调，先用 `d:real` 复验，别只看 `test:agent:real`。

### 5.2 那条抖动的链路是死代码，对学生没有影响

`test:agent:real` 打的是旧的 `AgentRuntime`（`server/core/agent.ts`）。实测：**没有任何 HTTP 路由调用 `agent.run()` / `agent.reply()`**，旧 `/api/chat` 在 `server/http/server.ts:303` 直接抛 `invalid_state`（"新版学习已启用，请使用受控 learning 学生事件入口"）。产品现在走 `ControlledRoles`（`server/agents/learning.ts`），d:real 的 tutor 轮每次都是 1–2 次工具就完成，没有复现轮次耗尽。

所以 3/6 的波动率影响的是一条已下线路径和一条冒烟脚本，不是学生看到的回复。**不要为了让这条脚本变绿去改它的断言**。

### 5.3 其他

1. **`max_tokens` 与思考 token 抢预算**：M3.1-Flash 是 adaptive thinking，思考 token 计入 `max_tokens`；留 8192 有被截断风险（模型返回 `finish_reason=length` 时本服务直接报错、不执行工具）。已默认提到 16384。
2. **对冲重发会双路计费**：20s 对冲机制在 MiniMax 上很少触发（实测工具轮 ~1.4s），但若真触发就是两份费用。与此前 GLM 的口径相同。
3. **旧 GLM Key 本地已被覆盖**：`.env.server` 那一行被新 Key 替换，本机不再有 GLM Coding Plan Key 备份（线上部署的环境变量里仍有）。要回退智谱，需要去智谱控制台重新取 Key，再配 `XIAON_GLM_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4` + `XIAON_GLM_THINKING=disabled`。
4. **套餐合规口径未变**：现在是 MiniMax 订阅 Key（`sk-cp-`），面向个人编程工具；用作儿童教学产品后台的适用性需确认。
