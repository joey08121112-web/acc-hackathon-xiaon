### SSH 不通时的部署通道：ECS 控制台「发送命令」（云助手，已实测可用）

浏览器打开实例详情页 → 全部操作 → 发送命令（或直接进 Workbench 免密终端，但见下方坑 1）。命令由阿里云内部通道在实例内执行，输出回显在弹窗「结果N」面板。**线上更新可完全不依赖 SSH/scp**：让服务器自己从 GitHub 拉代码构建。脚本要点（V3 实测通过，2026-11-20 23:5x 上线 b6efd17）：

1. `curl -sL -o src.zip https://codeload.github.com/joey08121112-web/acc-hackathon-xiaon/zip/<40位commit SHA>` ——**必须用 SHA，不能用 refs/heads/main**（codeload 按分支名会命中 CDN 缓存拿到旧 commit，这次就拿到了 c88970d 旧包）。
2. 解压后先 `test -f "$SRC/src/components/game/<新文件>"` 校验拿到的是新代码再继续（防缓存第二道保险）。
3. `docker build` 输出重定向到 /root/build.log，失败时 tail 回显。
4. 换容器流程同 §5（stop → `rm -rf /root/xiaon-data-restore` 后再 docker cp 备份 /data → rm → create 指向 journalctl 查到的当前隧道 URL → start/stop/恢复 data/start）。
5. 表单「执行超时」默认 60s，**要点开改成 600**（build 约 3 分钟）。
6. 验证：本地 curl 隧道地址 `/api/health` + 抓首页 `assets/index-*.js` 的 hash 与本地 `vite build` 产物比对、grep 新功能关键词。

### 云助手/Workbench 的坑（当晚实测）

1. **Workbench 网页终端输入丢字**：typeText/paste 进 xterm 只剩符号数字、字母全丢（疑似输入条或扩展拦截合成键盘事件），逐字慢输也没用——别在 Workbench 终端里敲命令。
2. **发送命令表单的命令框 setValue 可能静默失败**（浏览器窗口被切后台/失焦时）：填完必须回读 textarea value 确认是新命令再点执行；否则点「立即执行」跑的是上一次的旧命令（当晚 V1/V2 两次都因此重复执行了旧诊断脚本）。
3. **提交成功的判据**：执行后弹窗出现新的「结果N」页签；没新增就是没提交上。
4. 输出面板是 CodeMirror，AX 树要过几秒才读得到 value（可以切换结果页签触发渲染）；截图+视觉模型读输出也行但需要窗口可见。
