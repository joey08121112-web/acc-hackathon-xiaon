## 2. 先冻结协议，再实现基础

创建共享类型/JSON Schema及端口，完整覆盖总控中A必须冻结的协议面。先写协议测试/最小消费者编译样例，证明B和C可以独立实现各自端口，D可以统一注册。共享类型允许浏览器引用，不能把node/SQLite实现导入前端。

固定schemaVersion，声明拒绝未知字段、ID/版本校验和错误码。为字段定义实际含义，尤其是sessionId、attemptId、operationId、evidenceRevision、提示/答案暴露、历史时间可信度、报告和计划不可变版本。避免所有对象用any或任意JSON糊过去。

## 3. 本地服务与模型适配

- 新增Node/TypeScript服务、SQLite迁移、repository、Clock、HTTP路由、健康检查、最小本地会话和来源校验。
- 模型凭据移到服务端环境；清除当前ai.ts的浏览器直连密钥路径。前端客户端放src/agent-client，允许最小调整ai.ts来保持现有App调用兼容；聊天通过本地API，未配置/离线状态明确返回本地规则模式。
- 凭据不能进入Vite bundle、日志、报告或离线HTML。支持取消、超时和错误分类；模型失败不能伪装成真实工具已执行。
- 提供ModelProvider接口和真实HTTP适配器、可测试的合成适配器；只对实际选择的供应商协议实现，先查官方文档。不能静默把普通文本JSON当作原生function calling成功。
- 工具循环由程序执行，校验每次调用参数、角色、状态。默认单次请求最多4轮模型响应、6次工具执行；取消/预算耗尽后停止，保存可解释结果。

## 4. 第一批真实工具

实现并注册：get_learning_context、query_learning_evidence、get_skill_state、select_task、grade_attempt。

- 查询工具读取SQLite当前合成用户记录；没有记录返回空/尚未观察。
- A的选题和判题可通过最小legacy adapter复用现有可信题库及correct()，不要重写data.ts；清楚标明能力范围。B后续通过端口替换为知识点和rubric引擎。
- get_skill_state可返回基于已有记录的有限legacy观察，不能假装B的跨次能力规则已实现。
- grade_attempt只接受已经由学生提交事件保存的attemptId；从服务端查题目、版本及答案，不相信模型传入的正确答案。
- 建立学生提交attempt、提示/暴露事件的程序入口，原始记录由真实UI/API事件产生，模型不可编造。模型请求提示的后续工具schema可提前声明，未实现必须返回unavailable。
- 工具结果带证据ID和数据版本。教师答案与完整rubric只给必要评分路径，不出现在普通题目/辅导上下文及学生API。
- 偏好记忆只在开启且条目active/有效/相关时进入上下文；关闭和删除后从之后请求移除。缓存不得绕过权限。暂不实现任意SQL/文件/网络/代码执行工具。

## 5. 持久化、迁移与可测试性

提供受控旧进度导入入口/adapter：导出预览、明确范围后导入，事务化、可重试、保留原浏览器数据；A先完成服务端导入能力，D接UI。不自动读取/清空用户浏览器。旧timeLabel不能补造年份、场次和跨天证据。数据库schema支持B/C的证据、报告、计划和复习版本，但先不替它们实现规则。

为B/C提供临时SQLite夹具与repository测试工具；他们不需要修改你的package和lockfile。准备稳定命令：基础测试、B专属测试、C专属测试、D集成测试和总测试，尚无文件时明确未覆盖，不能把零测试当成功。分配独立测试端口并可环境覆盖。

## 6. 必须验收

先写失败用例，再完成：

1. 模拟模型发tool call → 真实handler查数据库 → 模型收到tool result → 最终回复；保存去敏轨迹。
2. 未知工具、无效参数、越权角色、伪造题号/答案、未保存attempt均被拒绝。
3. 重试同operationId不会重复尝试或重复记忆；重启服务仍能读取记录。
4. 记忆开关关闭、停止使用、删除后，不进入之后模型上下文。
5. 超时、取消、模型无工具能力、预算耗尽均有明确可恢复结果。
6. 用哨兵测试密钥核查实际前端bundle不含该值；不要用真密钥做泄露探针。
7. 导入重复/部分失败/未知旧时间；原文件保留，事务失败不留半份数据。
8. 现有npm test、npm run build按当前基线复核，UI兼容必要时定向浏览器验证。

若已安全配置真实模型，可以用合成数据跑一次真实tool call；未配置时完成其余工作并标明未运行，不能用mock替代这项结论。
