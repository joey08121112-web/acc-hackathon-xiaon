# C排程规则与四画像

默认1、3、7、14天是待验证产品策略，不称遗忘曲线最优。一天精确24小时；完成/到期保存ISO UTC，日期展示和“当天”判断使用Asia/Shanghai。

| 触发 | 当前阶段与下一安排 | 边界 |
| --- | --- | --- |
| 学生确认且有可信完成记录 | stage=0；无帮助正确从完成起1天 | 来源为真实场次、完整暴露历史和已保存评分，不补旧timeLabel |
| 到期、跨场次、未见题首次独立正确，距此前结果至少24小时且上海日期不同 | stage 0→1从完成起3天；1→2起7天；2→3起14天；3→4本轮completed | 本轮4次检查在第1/4/11/25天；不能当天刷完，不自动开始下一轮 |
| 提示/帮助后正确 | 保持阶段，完成起12小时 | 不作为未见新题独立检验，进级仍受最低间隔限制 |
| 错误 | 保持阶段，完成起6小时 | 先建议具体知识点支持再复测，不推断整体能力 |
| needs_review | 保持阶段，完成起24小时 | 待核查不是确定错误，不推进稳定状态 |
| 已见/原题、同场次或间隔不足的正确 | 保持阶段，不早于原安排或完成起24小时 | 区分原题、当天修改、延迟新题 |
| 缺席/查询 | 不升级、不新增结果/负面能力证据 | 到期保留，普通重复查询不写数据库 |
| 学生改期 | 新review revision保留originalDueAt与from/to/原因/时间 | 上海零点，今天不早于现在；旧revision拒绝 |
| 暂不开始/休息 | paused，可查看，不催促、不自动开题 | 新证据或未接受草案不妨碍暂停当前确认计划，仍校验当前计划ID |
| 主动恢复 | 逾期项恢复起24小时 | 同知识点一个任务，不堆积补做 |
| 减量 | 多项留首项；单项改为1分钟已有步骤回顾，task=null | 不把整道3分钟题改称1分钟 |
| 评分更正 | 用最新supersedes评分重放并追加review revision | 保留实际改期/暂停；旧尝试、结果、确认和报告不回写 |

构造器可配置ReviewPolicy的intervalDays/minimumAdvanceHours/helpRetryHours/errorRetryHours。首版只支持数据库初始化时固定策略，不支持已有数据热迁移。待核查默认24小时；预算1–120分钟，小数预算预计分钟向下取整，任务总量不超预算。

## 选题

到期且需支持 → 提示依赖/近期困难 → 证据不足 → 已独立待延迟检查。selectReviewTarget允许学生指定目标，返回候选、理由、依据和替代项。真实未结束场次统计计算题，刷新不重置；暂停时等待学生恢复。先修知识点至少有真实尝试才进候选；requireUnderstandLogicFirst=true和calculationLimit=10保留，最终由D及A学生事件门控。

已见题面、提示、答案/聊天帮助、题目旧版本或原题尝试不包装成未见新题。未见题不足、预算/先修不满足返回exhausted及原因，原题回顾单独标注。复习完成后下一队列task=null，D在学生愿意继续时重新选择，避免重开刚做的题。

## 四种合成画像

完整输入AssessmentSnapshot与规则输出PlanProposal/ReportSnapshot见evidence/four-profiles.json。全部合成，未调用B评分器或真实模型。

| 输入 | 6分钟预算输出 |
| --- | --- |
| brackets去括号提示依赖 completed_with_help | 提示帮助过渡到独立处理；3分钟具体步骤支持+3分钟未见迁移；初始12小时复查 |
| relations建模关系困难 needs_support | 厘清具体关系和步骤；3分钟支持+3分钟独立迁移；初始6小时复测 |
| brackets已有跨次独立 cross_session_independent | 3分钟delayed_check，不重复入门辅导；输入含相隔3天的两次合成独立记录 |
| meaning完全无记录 unobserved | 3分钟可选理解探索；不推断弱、不创建虚构到期复习 |

支持项可无整题绑定，只建议看一个具体步骤；不把建议说成已执行。正式文字润色由D的报告/计划Agent完成。

## 历史与幂等

repository.once保证同operationId同请求重放、不同请求冲突，失败事务无部分写入。同日同证据revision和预算复用草案，跨上海日期可生成新草案但不替换学生确认计划。报告同证据revision复用，新依据产生新报告及知识点状态变化。历史修订只附加basisRevised/replacementId投影，不修改原快照。

PlanVersion是当时确认快照，实时完成状态从currentReviewItems读取；新确认链接previousVersionId，旧确认不能覆盖较新计划。原始尝试/评分与历史保留，C完全不读取或新增memories。
