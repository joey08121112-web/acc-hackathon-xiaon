## 第一期 A：改造一，首页综合模式的界面（约 2.5 天，第一优先）

场景：初一学生考差了，打开 app。小N第一时间主动开口；以平复情绪为主，轻松地聊成绩和哪里没考好；聊天中顺带留意理解和逻辑（后端由 Claude 做）；结束时给对话小结和计划建议，在心情和时间合适时建议去专业模式（现有五维探索）。对应海报 01、02。

1. **首页换成对话，小N先开口**：首页上半部分用 `ChatPanel`（小N形象、气泡、话筒、打字框、快捷回复），不用再点「先聊聊」。打开时调用 `/api/learning/greeting`，用返回的 `text` 作为小N第一句：首次见面是默认问候；再次见面引用上次的对话小结或记忆，例如「上次你说应用题读着绕，这几天怎么样？」。失败时用默认问候。「休息」状态和「上次停在这里」保留，原 `chat` 页改为跳回首页。
2. **快捷回复用海报的说法**：「我考砸了，不想说话」「我怕爸妈问成绩」「我明明努力了，还是没考好」「陪我看看这张卷子吧」「不想聊学习了，聊点别的吧」，另加常驻的「今天先聊到这」。点击时带上对应 `intent`（例如「陪我看看这张卷子吧」是 `study`，「聊点别的吧」是 `life`）。
3. **陪聊提示词**（`prompts/companion.ts`）：可以聊朋友、兴趣、比赛和今天的疲惫；复述感受、一次一个问题；不说教。长度和朗读规则沿用通用规则。
4. **确定需求**（`NeedsCheckCard`）：回复带 `needsCheck: true` 时，显示三个选项：「继续聊聊」「看看哪里没考好」「做个正式测试」。只出现一次。
5. **切到专业模式**（`ModeSwitchCard`）：回复带 `modeSuggestion`，或学生选了「做个正式测试」时，显示说明卡：专业模式会用几道题看看理解、逻辑、计算、建模、空间想象，可以随时暂停。学生点「去专业模式」才调用现有 `learning/start`（`mode: exploration`）并跳到探索页；点「先不了」就留在对话。
6. **问学习**：回复带 `askStudy: true` 时，显示小N的一句轻问和两个按钮：「好呀，看看」（`intent: study`）和「今天先不了」（`intent: decline_study`）。
7. **引导上传或讲给小N听**：回复带 `askProblem: true` 时，显示 zCode 的 `ProblemCapture`（拍一张 / 说给我听 / 从题库挑）。本路只负责布局，不实现它的内容。
8. **对话小结**（`ConversationSummaryView`）：学生点「今天先聊到这」时调用 `/api/learning/conversation/end`，展示返回的小结：聊了什么、对话观察（标「待专业模式确认」，附原话）、和上次比、计划建议、专业模式建议。计划建议旁有「转成正式计划」按钮（进入现有计划页，由学生确认）。如果本次做过题，小结里嵌入进步卡。
9. **告知**：首次介绍（onboarding）里加一句：「聊天时小N会留意你怎么读题、怎么想，帮你找方法，不打分。」
10. **收起工程用语**：阶段 0 已用 `src/agents/devMode.ts` 把服务模式条和 Agent 轨迹接到开关上。本路在「我的与设置」里加「评委 / 开发者模式」开关，默认关；首页和设置页里其余学生能看到的工程用语（SQLite、证据版本等）也一并收进这个开关。
11. **样式**：写在 `src/styles/home.css`。手机 390 宽下键盘弹起时输入框不被遮挡。
12. 离线规则版（未连本地服务）保留旧首页按钮，不受影响。

## 第二期：专业模式界面、评测报告页、成长档案（约 3 天）

等 Claude 的第二期契约补丁合入 main 并打 tag `revamp-base2` 后，从它新建分支 `revamp/h2-professional-ui`。先读 `交付/claude/CONTRACT-PHASE2.md`。新代码放在 `src/components/professional/`。

1. **底部导航**：第二个「探索」改名「专业模式」（`App.tsx` 底部导航区块）。
2. **进入说明**：大约多久、可以随时暂停、五个模块依次进行、不打总分。学生点「开始」才开始。从综合模式小结的建议进入时同样显示。
3. **面试式对话**（`ProfessionalModeView`）：聊天式界面，小N一次说一道题或一句追问，学生在下方作答（文字、选项或话筒）。顶部五个模块依次点亮，可以复用现有五维地图的形象作进度。语气轻松，像闯关。始终有「先暂停」按钮，暂停后回到首页；再次进入时显示「上次停在：计算」并接着测。
4. **评测报告页**（`ProfessionalReportView`）：每个模块一张卡片，显示等级（掌握得不错 / 部分掌握 / 需要加强 / 还没测到）、依据原话（可展开）、学习建议；顶部说明「本次观察，不是总分，不排名」。下方是与综合模式观察的对照、和上次比，以及进入月阶段规划的按钮（zCode 的 `MonthStageView`）。历史报告可以切换查看。
5. **成长档案**（`GrowthArchive`，挂在成长页）：按月显示五个模块的等级变化（数据来自 zCode 的趋势接口），并把同月的对话小结、进步卡串在一起。
6. 现有工程用语照第一期的开发者模式开关处理。

测试：不点「开始」不开始；暂停后续测接在正确模块；报告不显示任何总分或排名用语；没测的模块显示「还没测到」；手机 390 宽走一遍完整测评与报告（用模拟模型，本路自建浏览器配置）。

## 第三期：改造四 B 线，模型出题与审核（约 3–4 天）

从第二期集成后的 main 新建分支 `revamp/h3-variant-audit`。输入是已确认的错题记录，输出是一道经过审核、可以进入复习的新题。新代码放在 `server/plugins/generation/variant/`，不改 E1 现有模板文件。

**审核机制（全部通过才发布）**

1. 生成：模型出题面、参考答案和分步解法；答案和解法只存服务端。
2. 结构检查（程序）：题面完整；知识点与错题记录一致；题面里没有泄露答案；数值在七年级难度范围内。
3. 独立盲解两次：两次独立调用只看题面解题；出题答案和两次盲解三者一致才通过。能用程序算的（代数式、数值）再用现有判题器算一遍。
4. 去重：与已有题按内容指纹比对。
5. 发布：固定版本保存；学生确认后才展示题面并记录暴露。任何一步不过就不发布，提示「这次没出好，先做题库里的同类题」。
6. 判分：能程序判就程序判；否则模型按参考答案判，不确定标「待核对」，待核对的作答不推动复习阶段。
7. 事后纠错：学生可以点「这题好像有问题」，该题立即下架，相关作答不计入复习；每次审核的结果和原因都留记录，供团队抽查。

做题时仍走 Claude 实现的「一起思考」，完成前不给答案。沿用现有限额（每场 5 道、每天 12 次）。需要改评分或复习模块（`server/plugins/assessment/**`、`server/plugins/planning/**`）时，先写契约变更申请。
